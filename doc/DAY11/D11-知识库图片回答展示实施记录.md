# DAY11：知识库图片回答展示

状态：已完成。最终回答可以明确选择本轮已读取的 Markdown、DOCX、XLSX 视觉来源，并在回答下方展示受当前 Run 快照授权的原图；三种格式均已完成真实问答与原图接口验证。

## 实现范围

- 最终结构化输出由 `answer + citationIds` 扩展为 `answer + citationIds + imageCitationIds`。只有用户明确要求查找、给出或展示图片时，模型才可选择最多 4 张图片。
- 最终模型只获得来源编号、标题、视觉描述和 `canDisplayImage`，不接触原图地址、存储键或视觉资产 ID。
- 模型正文中的 Markdown 图片、HTML `img` 和图片 URL 不具备来源授权：客户端禁止加载模型图片标记，服务端在完成前移除图片标记并以替换事件收敛正文。真正图片只能来自经校验的 `imageCitationIds`。
- 服务端重新校验图片编号必须属于本轮实际读取证据，并且定位格式只能是 `markdown-visual`、`docx-visual` 或 `xlsx-visual`；图片选择自动进入回答来源，不能产生没有来源卡片的孤立图片。
- 展示意图作为回答引用的可选元数据保存在既有消息 JSON 和 Run 完成事件中，不新增数据库列；旧历史引用没有该字段时保持原展示行为。
- 客户端根据 `runId + chunkId` 生成现有受鉴权 `/asset` 地址。图片加载中显示占位状态，读取失败显示真实失败状态；缩略图可通过鼠标或键盘打开大图 Dialog，图片卡片不重复提供“查看来源”按钮，回答底部来源标签继续承担来源抽屉入口。
- 图片只在最终结构对象通过校验、来源再次授权且 Run 成功完成后出现；流式草稿和执行过程不能提前展示未授权图片。

## 当前边界

- 本阶段展示知识库中已经完成视觉分析的原图，不生成新图片，也不在 Run 中再次调用视觉模型。
- PDF 视觉页暂不进入回答内图片选择；其现有来源抽屉和页码预览不受影响。
- 模型只能从本轮 Agent 实际读取的视觉证据中选择图片。仅出现在检索候选但未读取的图片不会被输出。
- 一轮最多展示 4 张，避免回答页面和模型选择字段无界增长；其余匹配项仍可通过后续追问继续查找。
