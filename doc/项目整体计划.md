# VaultAgent MVP 执行计划

更新日期：2026-09-05  
周期：4 周，单人全职约 20 个工作日。  
状态：执行方案已完成第三次审计，尚未开始实现。已按个人 Obsidian 知识库的真实资料形态调整格式优先级；线上选定 Vercel 免费托管体系，模型与搜索统一通过 AI Gateway 计费。

## 1. 产品目标与两种运行模式

VaultAgent 是个人知识库聊天与审计平台。用户导入自己的笔记和文档，系统建立索引，随后通过会话进行知识检索、关联阅读、问题检测，以及对公开技术实体和官方资料的外部证据核验。

### 1.1 本地自部署：主要产品形态

> Docker 启动 → 首次初始化 → 默认进入“我的知识库” → 上传多个文件或 Vault ZIP → 自动解析与索引 → 新建会话并提问。

- 默认只有一个“我的知识库”，用户不用先创建或选择知识库。
- 原始文件保存在用户部署机器的私有目录；解析结果、元数据、向量、会话和任务写入用户自己的 PostgreSQL。
- 默认持久保存，关闭浏览器或重启应用不删除；24 小时 TTL 不适用于本地个人知识库。
- 浏览器上传会复制文件进入系统；第一版不监控和回写原 Obsidian 目录。
- 已导入文档可以继续追加，支持删除和重新索引。
- 多知识库管理不是 P0；底层保留 workspace_id，方便后续扩展。
- 本地实例默认单人使用，初始化一个本地管理员。登录 Session 到期不删除其知识库；Docker 默认只绑定 localhost，对外开放前必须配置认证与 HTTPS。
- 本地存储不等于完全离线：使用云端生成、Embedding、rerank 时仍会外发相应内容，首次配置明确告知。

### 1.2 公开体验站：访客独立使用

> 打开链接 → 直接进入带示例资料的聊天页 → 点击推荐问题或自行提问 → 查看引用、审计结果与执行记录。

- 不要求访客注册、填 API Key 或由项目作者现场讲解。
- 可切换到“导入我的资料”，在当前访客隔离空间中体验。
- 示例资料只读共享；访客上传、会话和任务互相隔离。
- 访客私人资料默认 24 小时过期，页面提供立即删除。
- 示例历史报告明确标记生成时间、模型与资料版本；真实执行入口不返回伪造的预制答案。
- 托管免费资源耗尽或模型/搜索预算用完时显示原因，保留文件浏览和历史报告；不自动升级收费托管或昂贵模型。
- 不限定托管地区，默认使用 Vercel 平台地址；验证普通访客网络的页面、上传和流式体验。

### 1.3 四周版本的生产边界

本项目面向个人本地实例和小规模公开体验，不承诺企业级高可用或无限扩展。四周版本的“可生产运行”指：从空环境真实部署，使用真实文件走通导入、检索、回答、引用与删除；在公开声明的容量内做到数据隔离、费用有界、失败可恢复，并提供必要的 Trace、评测和备份恢复证据。

- 不以增加中间件证明生产性；没有实测需要时不增加 Redis、独立向量数据库、LangGraph、多 Agent 或通用策略平台。
- 发布硬门禁覆盖普通 Obsidian Markdown、TXT、文本 PDF、常规 DOCX、基础 XLSX，以及 PNG/JPEG 和文档内嵌图片的有界语义分析。支持矩阵必须逐项说明可靠、部分支持与不支持，不能把“文件可上传”写成“内容已完整理解”。
- 为控制四周范围，P0 只保留自建 Vault MCP；GitHub MCP、浏览器文件夹选择、批量扫描/OCR、复杂 Office 版式和在线标注进入 P1。D1–D2 验证关键 SDK 与双环境，D7 决定是否开放私人上传，D10 冻结聊天/RAG，D15 冻结全部功能。本地 Workflow 可靠运行属于主要产品硬门禁，失败时延期或重新评审架构。四周内不临时引入第二套队列或 Agent 框架，也不降低隔离、引用、删除与费用控制要求。

## 2. 界面：左侧会话，中央聊天

默认采用聊天平台布局，不把文件树作为常驻左侧主导航。

| 区域 | 内容 |
|---|---|
| 左侧栏 | 新建会话、会话搜索、历史会话、重命名/删除；底部放知识库、审计和设置入口；访客看不到管理入口 |
| 中央区域 | 消息列表、流式回答、引用标记、审计报告卡片、底部固定输入框 |
| 输入框 | 多文件选择、拖拽上传、上传进度；导入目标明确为当前知识库 |
| 右侧抽屉 | 点击引用后打开原文、PDF 页、图片或证据比较，默认关闭 |
| Run 执行过程 | 最终回答上方的耗时/状态摘要，可展开阶段说明与工具活动，默认折叠 |

会话要求：

- 会话、消息、Agent Run 分开建模；一次会话可以产生多次 Run。
- 左侧会话项只显示标题，不显示会话摘要，也不提供悬停摘要。
- P0 用首条问题截断生成会话标题，并允许手动重命名；模型自动命名放入 P1，避免增加一次异步调用和写回竞态。
- 追问理解使用第 7.4 节的有界历史与结构化 Run State，不依赖模型生成的会话摘要。
- 历史持久保存，支持多轮追问、停止生成、失败重试。
- 删除会话不等于删除知识库文件，界面明确区分。
- 会话默认检索“我的知识库”，可限制到本次上传的文件或选定文档。
- 单次 Run 固定资料快照；追加文件后，后续 Run 使用新快照，并提示资料范围变化。
- 首次空状态提示上传文件；示例站空状态提供三个直接可执行的问题。
- 执行时默认只显示简短阶段和取消按钮，不展示完整私密思维链。
- 手机端侧栏收起，输入框和引用抽屉可用。

建议页面：

| 路由 | 用途 |
|---|---|
| /、/chat/[id] | 默认聊天入口与历史会话 |
| /library | 导入文件、文件清单、解析状态、删除与重新索引 |
| /imports/[id] | 导入进度与失败说明 |
| /audit | 结构问题列表、主题审计入口、证据与建议 |
| /runs/[id] | 任务详情与报告，入口来自会话 |
| /settings | 本地模型配置、数据管理；公开站只显示访客可操作项 |
| /admin | 仅所有者：基础运行监测、成本与静态评测报告入口 |

### 2.1 一次 Run 的交互规范

一次用户提交产生一个 Run。按用户截图设计，执行过程与最终答案属于同一次执行。

折叠后：

```text
用时 3 分 11 秒  ›
────────────────────────
最终回答正文、引用与建议
```

展开后：

```text
用时 3 分 11 秒  ⌄
────────────────────────
我先检索你的笔记，并核对其中的版本相关结论。
⌕ 搜索知识库 · 找到 8 个候选
▤ 读取了 3 篇笔记

查到了，发现两条可能过期的结论，接下来核对官方资料。
⌕ 搜索网页 · 2 次
↗ 读取官方文档与发布记录

一条结论只适用于旧版本，另一条目前证据不足。
✓ 引用检查完成 · 1 项待确认
────────────────────────
最终回答正文、引用与建议
```

- 执行中标题显示“正在检索 · 已用时 12 秒”等真实状态。过程不折叠，下一轮调用不强制收起，结论出来之后直接折叠，用户可以展开
- 允许“简短说明 → 工作 → 阶段性回答 → 继续工作”反复出现；阶段性回答先于后续工具执行显示，不在最终完成后伪造过程。
- 公开阶段说明只包含简短计划、已证实的进展和下一步动作；不接收或渲染模型私密推理内容。
- 阶段说明与工具活动按真实事件顺序交错排列，不拆成许多独立助手气泡。
- 最终回答在折叠区外流式输出一次。中间模型输出结束不等于整个 Run 完成，不能误渲染成最终答案。
- 工具活动默认紧凑一行，可二次展开脱敏参数、结果摘录、来源和错误。完成数量与成功状态由服务器校验。
- 失败、取消、部分完成各有状态。失败保留已有证据，不显示成功标记。
- 用 AI Elements Conversation、MessageResponse、Tool、PromptInput 配合 shadcn 折叠容器；按截图默认简洁浅色。
- 不额外启动一个模型专门写进度，也不要求每个工具都生成说明。

### 2.2 事件与恢复

RunEvent 保存 run_id、单调 seq、event_id、type、step_id、created_at 和脱敏 payload。事件包括 run_started、stage_message、tool_started、tool_finished、verification、final_delta、run_completed、run_failed、run_cancelled。

先持久化事件再发布；文本增量按短时间窗口合并写库，避免每个 token 写库。并行工具用 tool_call_id 关联，重试用 attempt 区分。浏览器按 seq 去重与补齐，最终答案使用独立 message_id。Run 完成后刷新仍保持相同结构和顺序。

- 最终消息记录 generation_attempt，同一 Run 只有一个有效生成尝试。最终正文一旦已有增量持久化，后续失败不自动重新生成；旧半截答案标记未完成，用户主动重试时创建新尝试并明确替换显示，不把两次生成直接拼接。
- 最终消息、Run 终态和完成事件在同一业务事务提交；取消、删除或资料过期后，旧尝试不能继续写回。
- 恢复验收在流式输出中间强制中断；刷新后不得出现重复正文、两个最终答案、双重完成或已取消任务重新完成。

验收：至少两轮“说明/阶段回答 → 工具 → 继续执行”；展开时看到实时过程，收起时只看到耗时标题和最终答案，刷新/断线及生成重试不会重复或拼接不同答案。

| Excel | ExcelJS + 有界 OOXML 关系解析 | P0 读取基础 XLSX 的工作表、单元格、公式/缓存值及内嵌图片；D1 fixture 通过后锁定版本 |
| 图片 | Qwen 3.7 Flash | P0 保存、预览并按导入选项有界分析；原图、位置、模型提取和解释分开 |
| Embedding | Gateway：alibaba/qwen3-embedding-0.6b | 低价多语言向量化，维度与模型版本固定进入索引 |

| 外部搜索 | AI Gateway 内置 Perplexity Search | 配合 Qwen 搜索网页，模型与搜索统一 Gateway 入口 |

[Drizzle](https://orm.drizzle.team/docs/overview) 是应用访问数据库的代码库，不是数据库、服务或 Agent。选择它是为了表结构、查询和 TypeScript 类型一致；不替代 PostgreSQL，也不负责生成向量。

[pgvector](https://github.com/pgvector/pgvector) 为 PostgreSQL 提供向量存储和相似度检索。当前项目不需要再部署 Qdrant、Milvus 或 Pinecone；达到容量/性能瓶颈后再依据实测决定。

### 3.2 Next.js 与后台任务的分工

Next.js 全栈适合本项目：页面、会话 API、鉴权、上传控制和流式接口在同一项目。耗时解析和 Agent 由 Workflow 分步骤执行，复用同一套 TypeScript 业务代码。

- 线上不在 Vercel Functions 内启动永久轮询进程；取消原方案的独立 pg-boss Worker。
- Worker 的后台处理职责可以放在 Vercel，由 Workflow 调度有时限的函数执行；普通常驻 Node.js Worker 不能按原样搬到 Hobby Functions。当前 Fluid Compute 下 Hobby 单次函数最长 300 秒，Workflow 可以跨多次函数执行继续，但每一步仍受此限制。[官方执行限制](https://vercel.com/docs/functions/limitations)
- Workflow 负责持久调度，AI SDK 负责模型、工具协议和 Agent Loop，不引入 LangGraph 或第二套队列框架。
- 使用 AI SDK 显式逐步循环，将一次模型决策、工具执行、结果保存划分为可恢复步骤；不把整个多轮 ToolLoopAgent 包成一个会整段重试的大步骤。
- 解析按文件/页分批，Embedding 按批次保存；单步骤受函数超时限制。
- Workflow 状态只传 Run ID、文件版本 ID、步骤 ID 等小数据；模型上下文与证据由步骤内部鉴权后从业务库读取，避免私人正文进入平台历史。
- Next.js 返回 Run/Import ID 后，浏览器订阅进度。关闭页面不取消任务；after() 和悬空 Promise 不用于保证后台完成。
- 任务提交使用幂等业务 ID；业务库记录待调度状态，启动失败可重试；同一 Run 仅一个有效执行租约。
- 业务库是任务状态的事实来源。提交请求、任务完成和状态查询会尝试补调度过期的 queued 任务；受保护的定时对账补充发现遗留任务，管理页提供明确的重新调度入口，不把数据库中的 queued 当作已成功启动。
- 任务状态固定为 queued、running、completed、partial、failed、cancelled；排队和运行分别设置时限。P0 对不允许外发的内容直接拒绝联网，不建设暂停等待审批的通用状态机。
- 本地使用同一 Workflow 定义和 @workflow/world-postgres；其内嵌 Worker 调度任务，不是另一个 AI Agent。
- Docker Compose 启动 Next.js、PostgreSQL/pgvector 与文件卷；不要求用户手动启动第二个后台程序。
- PostgreSQL World 官方当前定位为参考实现；D1–D2 验证 Next standalone、任务启动、进程关闭，以及步骤执行中断和“外部调用已完成、业务事务尚未提交”两种杀进程恢复。步骤写入、最终答案和预算对账必须容忍至少一次执行；未通过前不宣称可靠自部署已经完成。
- PostgreSQL World 当前不会自动清理一般 Workflow Run 历史。本地把 Workflow 与业务表分开统计，D15 前测量增长并声明已验证的保留 Run 上限；达到上限时停止新任务并提示维护。除非锁定版本提供并验证安全清理方式，P0 不直接编写删除其内部表的通用清理器。

依据：[Workflow PostgreSQL World](https://github.com/vercel/workflow/tree/main/packages/world-postgres)。

### 3.3 Vercel 生态边界

采用 Next.js、AI SDK、AI Elements、AI Gateway、Workflow、私有 Blob；数据库使用 Neon Free 的 PostgreSQL + pgvector。

线上托管免费，不再限定中国平台；模型与搜索按 Gateway 用量计费。Docker 本地版文件和数据库属于用户自己的机器；云模型和搜索仍访问 Gateway。

来源：[Gateway 实时模型目录](https://ai-gateway.vercel.sh/v1/models)、[Qwen 3.7 Flash](https://vercel.com/ai-gateway/models/qwen3.7-flash)、[Qwen3 Embedding 0.6B](https://vercel.com/ai-gateway/models/qwen3-embedding-0.6b)、[Voyage Rerank 2.5 Lite](https://vercel.com/ai-gateway/models/rerank-2.5-lite)。

主模型选择理由：

- Gateway 明确列出工具调用、文本和图片输入能力，能够覆盖 P0；PDF 仍由 PDF.js 提取文本和页码，只把受限页面渲染结果交给视觉模型。
- 相比目录中 Qwen 3.8 Flash 的基础输入 $0.16、输出 $0.47 / 百万 tokens，3.7 Flash 更适合当前低成本开发目标。
- 同一个主模型承担问答、审计与图片分析，不新增视觉模型。
- 结构化输出先使用非思考模式；工具循环的具体参数按安装版本文档实现和验证，不向 UI/日志输出完整私密推理。
- 能力支持不等于质量达标：第 1 天验证 tools、结构化输出、流式和用量；第 2 周开始用固定测试集检验多轮任务。
- 不直接把完整 Vault 或长 PDF 交给模型；仍保留解析、检索和原文定位。
- P0 图片分析是用户可见、可关闭且有数量/像素/预算上限的导入选项；未分析、超过上限或低置信度的图片明确标记，不能作为已确认文本证据。批量 OCR 与扫描件完整识别进入 P1。

## 5. 线上部署：Vercel 优先

### 5.1 部署结构

```text
浏览器
  ├─ Vercel：Next.js 页面、API、鉴权、事件流、Vault MCP HTTP
  └─ 授权直传：Vercel 私有 Blob
       Next.js → Workflow：解析、索引、Agent、到期清理
                    ├─ Neon PostgreSQL + pgvector
                    ├─ 私有 Blob
                    └─ AI Gateway：生成、Embedding、rerank、网页搜索
```

- 一个仓库、一个 Vercel 应用，前端和 Agent API 同源，数据库/Blob/函数优先邻近区域。
- Demo Vault 脱敏素材随仓库发布，通过幂等种子任务预建只读索引；不在每次访问或构建时重新向量化。
- 服务端检查 Visitor、文件额度和对象路径后签发短期上传权限；浏览器直传私有 Blob，上传回调再次核验真实大小、类型与归属再入队。
- 不把大文件经 Next.js 请求体中转；Vercel Functions 请求体限制当前 4.5 MB。PDF 预览鉴权后流式/Range 读取，不把大文件塞进 JSON。[Functions 限制](https://vercel.com/docs/functions/limitations)
- 私人 Blob 不公开读取，分享聊天页 URL 不赋予文件权限。[私有 Blob](https://vercel.com/docs/vercel-blob/private-storage)
- SSE 仅订阅进度，不负责调度。RunEvent 和最终答案保存业务库；订阅端按 seq 从业务库补齐，不依赖单个函数实例的内存广播。活跃任务短时订阅、空闲关闭，具体查询间隔和批量大小按 D2 实测，避免持续轮询唤醒数据库。

### 5.3 本地部署与清理

本地使用私有文件卷、PostgreSQL/pgvector 和 PostgreSQL World，复用线上解析、检索、Agent、事件与权限逻辑。

## 6. 导入与向量流水线

### 6.1 导入入口

P0 同时支持：

- 单文件或一次多选 MD、TXT、PDF、DOCX、XLSX、PNG、JPEG。
- 拖拽多个文件。
- Obsidian Vault ZIP，保留目录和相对路径。

浏览器文件夹选择进入 P1；ZIP 内的受支持文件按同一解析器处理，其他文件保留清单并标记不支持，不静默丢失。只上传部分笔记时，未随附的图片、附件与 Wikilink 目标显示“当前导入范围内未找到”，不能断言用户原 Vault 损坏。

文件系统路径、单批导入关系和名称冲突必须可见；同名文件不得静默覆盖，上传时给出替换为新版本或保留副本的选择。

### 6.2 导入与存储

> 上传 → 校验与保存原文件 → 解析 → 切块 → 调用 Embedding 模型 → 向量及文本写入 PostgreSQL → 发布索引快照。

这一阶段是确定性的后台任务，不需要单独的“入库 Agent”。模型只承担 Embedding 或可选提取工作，调度、去重、重试与写库由程序执行。

- 线上授权直传私有 Blob，本地同源 API 流式写入私有卷；解析步骤按文件/页/批次有界处理。
- 每文件独立状态：pending、parsing、indexing、ready、unsupported、failed。
- ZIP 额外经过安全解压；普通文件直接进入解析，不走压缩流程。
- 同一所属用户内可以按内容哈希复用解析文本和向量，不跨私人用户去重；文件身份、目录、版本和路径相关链接始终独立，不能因内容相同而合并。
- 解析缓存键包含解析器版本；向量缓存键包含模型、维度、输入模板和切块版本。共享产物在没有有效文件引用后才能清理。
- 相同内容不重复生成索引；变化文件创建新版本。更新批次部分失败时保留旧可用快照并显示逐文件状态，全部必需文件成功后再原子发布候选快照；并发导入用快照版本检查避免相互覆盖。
- Run 固定文件版本集合与索引配置；不同 Embedding 模型、维度或输入模板产生的向量不能混合检索。删除或过期即时撤销旧快照读取权限。
- 本地资料归属持久 Owner；公开上传归属临时 Visitor，不能以浏览器会话 ID 充当本地资料的永久所有者。
- 重传少数文件是追加/更新；ZIP 重传默认也不隐式删除未出现的旧文件，完整快照替换须显式选择。
- 原文件保留原样；数据库保存解析文本、元数据、向量和文件位置，不要求把所有二进制塞入数据库。

### 6.2.1 文件修改、版本发布与历史引用

P0 不监控或回写用户原始 Obsidian 目录。用户修改本地文件后，通过重新上传单个文件、多文件或 Vault ZIP 触发增量更新；自动目录监听与双向同步属于 P2。

- 逻辑文件与文件版本分开建模：逻辑文件表示用户认识的文档，`file_version` 保存不可变内容、内容哈希、原始路径、解析器/索引版本、创建时间和处理状态。引用、chunk、派生附件与 Run 快照都绑定具体 `file_version_id`，不能只指向当前逻辑文件。
- 同一所属用户和逻辑路径下内容哈希未变化时跳过解析与 Embedding，并记录本次导入未产生新版本；哈希变化时创建候选版本，不原地覆盖当前版本。
- 候选版本完成校验、解析、切块和向量化后，以事务或等价原子操作发布新索引快照。处理失败时保留旧版本和旧快照可用，显示失败阶段，不把半成品加入检索。
- 一次 Run 启动时固定文件版本集合和索引配置；运行期间发布的新版本只供后续 Run 使用。界面提示正在执行的 Run 是否基于更新前快照，禁止一次回答混用同一逻辑文件的新旧版本。
- 历史消息和报告保留当时的版本引用、摘录、位置与内容哈希，并在逻辑文件已有新版本时显示“存在更新版本”。只要旧版本仍被有效 Run、报告或快照引用，就保留重现引用所需的原文和定位；旧原文件已清理时明确显示不可预览，不能把引用静默改到最新版。
- 路径相同而内容变化视为更新；路径变化而内容哈希相同时标记为可能移动/重命名，由用户选择更新路径或保留副本；路径和内容均变化时默认作为新文件，不能凭模型猜测合并。
- 重传部分文件只追加或更新这些文件，不把本批未出现的旧文件视为删除。只有用户明确选择“用本次完整 Vault 替换”时，系统才计算缺失文件清单并在确认后删除；候选快照发布前，旧快照继续可用。
- 一批更新默认全部必需文件成功后再发布。部分失败时保留旧快照并列出失败文件；P0 不自动发布新旧文件混合快照，避免用户误解当前资料范围。
- 当前版本长期按所属空间规则保留；未被有效 Run、报告、快照或其他文件关系引用的旧版本可延迟清理。配额统计包含旧版本、派生附件、失败残留和待删除数据，防止反复更新绕过容量限制。
- 用户主动删除逻辑文件时，先撤销所有版本访问并禁止相关任务继续写回，再按引用与保留策略清理原文件、chunk、向量和派生附件。公开 Visitor 的全部版本、引用正文与派生数据统一受其 `expires_at` 约束。

版本更新验收：同一文件原样重传不重复向量化；修改后生成新版本；新版本处理失败仍能检索旧版本；运行中更新不会混用版本；刷新历史回答仍指向当时版本；部分 ZIP 重传不会误删缺失文件；明确整库替换时才删除缺失文件。

### 6.3 解析与引用

| 格式 | 级别 | 解析 | 引用 |
|---|---|---|---|
| MD | P0 | AST、Frontmatter、Tags、Heading、Block ID、Callout、代码和链接 | 文件版本、标题路径、原始行号/Block ID |
| TXT | P0 | 编码检测和段落切分 | 文件版本、行号 |
| PDF | P0 | 文本层优先；可选对无有效文本或用户指定的少量页面渲染后做视觉分析 | 文件版本、PDF 物理页码、摘录；模型提取注明对应页面 |
| DOCX | P0 | 标题、段落、基础表格；提取内嵌图片并保留父文档关系 | 文件版本、标题、段落/表格序号，不伪造页码 |
| XLSX | P0 | 工作表、非空单元格、合并范围、基础表格、超链接、公式文本与缓存值；提取内嵌图片和锚点 | 文件版本、Sheet、单元格/区域；不把公式缓存值说成实时重算结果 |
| PNG/JPEG | P0 | 保存与预览；用户启用后由统一视觉步骤提取可检索描述和可见文字 | 原图、父文件/引用位置、模型与分析状态 |

- DOCX/XLSX 作为压缩容器限制条目数和解压总量，不读取会主动联网或访问宿主文件的外部关系；D1 用含表格、公式和内嵌图片的固定 fixture 验证解析器后锁定版本。[Mammoth 图片处理](https://github.com/mwilliamson/mammoth.js#custom-image-handlers)、[ExcelJS](https://github.com/exceljs/exceljs)
- ExcelJS 读取公式及已保存的缓存结果，但不计算公式；没有缓存值或可能过期时只索引公式文本并明确标记。复杂图表、透视表、宏语义和精确版式不在 P0。
- P0 不承诺批量扫描 PDF、手写体、异常字体、多栏、复杂图示的完整识别；逐文件/页显示可靠、部分支持、不支持或失败，解析成功不等于内容完整。[PDF.js API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html)
- 图片在多篇笔记或多个 Office 位置中出现时保存一个派生附件、多个引用关系；MD、DOCX、XLSX 和 PDF 页面的图片共用同一视觉分析步骤。
- 图片语义是模型派生结果，必须保存父文件版本、位置、模型版本和分析状态；检索命中时同时展示原图，低置信度内容不得独立支撑关键结论。
- Markdown 中引用的 PDF、DOCX、XLSX 和图片保存附件关系；附件随本批文件上传时独立解析并与来源笔记关联，未上传时只报告当前导入范围缺失。远程附件不自动下载。
- PDF 图片分析由用户选择页面；未选择时只候选无有效文本的页面，并受每批页数上限约束。带文本页面中的复杂图表不会因此自动宣称已理解。
- Wikilink 保存来源位置、目标路径、显示别名、标题或 Block ID；Backlink 从链接反向查询。
- 重名、大小写、相对路径和锚点歧义明确记录；代码块不误识别为链接。
- Markdown/网页 HTML 清洗，禁止执行脚本，不自动下载远程图片。
- 原文定位与向量检索文本分开；模型只引用证据 ID，服务器核对原文和归属。

### 6.4 检索与 rerank

> 用户问题 → 必要时改写追问 → 关键词召回 + 向量召回 → RRF 融合去重 → rerank → 读取 Top K 上下文/关联资料 → Agent 形成答案并验证引用。

- 文档块起始大小约 350～700 tokens，必要时重叠 50～80；按标题、段落、代码和页边界切分。
- PostgreSQL FTS 处理关键词；P0 使用应用侧统一中文分词并固定分词/归一化版本，避免依赖线上未确认支持的中文 PostgreSQL 扩展。中文、英文技术词、路径、标题和代码标识符分别加权并用混合查询样本验收。
- pgvector 存储 Embedding；小数据量先做权限范围内精确向量搜索，后续按实测增加 HNSW。
- 关键词 Top 20、向量 Top 20，融合后取最多 20 个候选交给 reranker，最终保留约 6～8 个。
- reranker 是评分模型，不是 Agent；它对“问题 + 候选文本”打分，不生成新的事实。
- P0 实现 rerank，提供开关和独立 Trace；设置超时，失败回退 RRF 并明确记录。
- rerank 只能改善已有候选的次序，不能找回未召回的证据；评测分别检查召回和排序。
- 关联扩展默认 1 跳、最多 2 跳，增加节点最多 20 个，不建设通用知识图谱。
- Embedding 的 query/document 输入模板、查询指令、维度、归一化方式和距离函数固定并实测；模型、输入模板、rerank、分词与切块版本都进入索引和评测记录。
- 云端 rerank 会外发候选文本，必须列入本地与公开站隐私说明。

## 7. Agent Loop 与审计

### 7.1 执行设计

> 任务分类 → 简短计划 → 检索与重排 → 读取与关联扩展 → 候选声明 → 必要时外部研究 → 对比证据 → 验证 → 完成或部分完成报告。

| 元素 | 实现 |
|---|---|
| State | 所有者、会话、Run、快照、目标、范围、计划、访问集合、证据、声明、问题、预算与检查点 |
| Plan | 结构化步骤和完成状态；服务器校验范围 |
| Tool Registry | Schema、只读权限、外发等级、超时、幂等性、结果上限和版本 |
| Observation | 工具事实摘要与真实结果引用 |
| Hypothesis | 待查证声明、版本和适用条件，不是私密思维链 |
| Evidence | 原文、定位、版本哈希、URL、发布时间/更新时间/抓取时间 |
| Verification | 程序检查引用真实性；受限模型比较证据支持、条件和反证 |
| Completion | 回答目标或范围内声明全部分类；不足则 partial，不伪装完成 |

候选问题分类：结构问题、重复、疑似冲突、可能过期、未找到支持证据。导入后自动跑结构规则，语义和联网审计按用户指定主题执行。

### 7.2 控制与恢复

| 限制 | 问答 | 审计 |
|---|---:|---:|
| 模型决策轮次上限 | 4 | 10 |
| 工具调用上限 | 6 | 14 |
| 累计 Token | 记录实际用量，受单 Run 费用预算约束 | 记录实际用量，受单 Run 费用预算约束 |
| 外部页面 | 2 | 5 |
| 候选声明 | 按问题 | 最多 15 条 |
| 运行时间上限 | 60 秒 | 180 秒 |

- 单请求上下文容量与累计 Run 用量分开控制；取消统一的 15K/40K 累计 Token 硬上限。每次请求前按实际价格档位预留费用，并给验证与最终答案留足额度。
- 免费公开站初始全局并发 1，单访客并发 1；数据库队列记录排队状态。
- 公开站初始限制为单访客最多 1 个等待任务、全站最多 3 个等待任务，排队超过 5 分钟结束为失败并允许用户重新提交。D7 根据真实耗时调整，不把队列做成无限缓冲区。
- 所有模型、验证、Embedding、rerank 和重试共享总配额；不把一次 Agent Run 当成一次模型请求。
- 模型请求可能已计费但 usage 丢失时，将预算预留标为待对账，不立即释放；SDK、Workflow 和业务层重试共用同一 attempt 上限，防止叠加重试突破预算。
- 临时错误最多重试 2 次；授权失败不重试，参数错误最多纠正一次。
- 最多重规划 2 次；连续 2 轮无新增证据时调整一次策略，仍无进展即停止。
- 已访问节点去重，相同读取复用；工具结果限长，避免上下文无限增长。
- 每次工具结果和模型步骤完成保存状态；租约、运行锁和幂等键控制重复执行。
- 恢复完整有效的最近模型消息与业务状态；不保证外部模型请求恰好一次或答案文字不变。
- 断开浏览器不取消任务，重新连接按事件序号补齐；主动取消停止后续调用。
- 公开数据过期/删除或本地用户删除资料后，旧任务禁止继续读取和恢复。

### 7.3 审计输出

每个 Finding 含：问题类型、严重程度、本地来源、外部证据、版本和时间、比较结果、支持与反证、置信等级、建议、人工确认标记、检查覆盖范围。

- 失效链接和缺失附件：规则匹配；不完整上传与原文损坏区分。
- 重复：哈希确认完全重复，相似召回生成近重复候选。
- 冲突：先对齐对象、版本、时间和条件，不能只比较两句话的表面含义。
- 过期：以官方版本资料核对，历史适用不等于当时错误。
- 缺乏证据：输出“本次未找到支持”，不等于结论错误。
- 观点变化：使用真实日期来源；没有历史快照不能编造历史。
- 置信度用高/中/低/未验证并给依据，不使用模型自报百分比。
- 同组织官网和 GitHub 是可比较材料，不自动算独立来源。
- 无法确认的图形流程、复杂图表或模糊截图输出未验证，提取结果必须关联原图，不用模型补造图中事实。

### 7.4 上下文与记忆：P0 最小实现

P0 实现有界上下文组装和 Run 工作状态；模型生成的滚动会话摘要、跨会话长期记忆延后到 P1。复用 PostgreSQL，不增加记忆服务、独立 Agent 或另一套向量数据库。

| 层次 | 内容 | 生命周期与用途 |
|---|---|---|
| 知识库 | 文件、版本、文本块、向量、链接 | 用户资料与可引用事实，通过 RAG 按需读取 |
| 会话记忆 | 最近完整对话、用户明确约束及更正 | 仅当前 Conversation；用于追问理解，不代替文档证据 |
| Run 工作状态 | 目标、计划、访问集合、证据 ID、待验证问题、预算 | 仅当前任务；用于 Agent Loop、中断恢复和避免重复搜索 |
| 长期偏好 | 回答语言、格式等用户主动保存的设置 | P1；用户可查看、修改和删除，不自动推断个人画像 |

上下文每次调用重新组装：固定系统规则与权限 → 当前问题和明确约束 → 最近完整对话 → Run 状态 → 当前相关证据和工具结果。数据库保存全部历史，不代表每轮全部发送给模型。

- P0 使用确定性裁剪：结果去重、限制 Top K、删除重复网页内容，大结果保存业务库并只发送必要摘录与可重读 ID。
- 始终保留当前问题、更正、范围约束、未完成工具调用、待验证声明和关键反证；工具调用与结果必须成对保留。
- 最近对话按实际模型窗口、输出预留和单 Run 预算选取；较早消息未进入本轮上下文时在 Trace 中记录，不伪装模型仍然记得。
- 当前关键证据保留原文摘录，旧证据只保留 ID、定位和简述；验证及最终引用前按 ID 重读原文。
- Token 统计包含系统提示、工具 Schema、历史与证据；具体阈值根据 D8–D10 实测固定，不能把价格档位当成模型容量上限。[模型说明](https://vercel.com/ai-gateway/models/qwen3.7-flash)
- P1 如确有长会话需求，再加入带来源消息范围和版本的结构化摘要；摘要只导航，不作为事实证据。
- 本地对话按用户删除规则保留，公开对话随 Visitor 过期；P0 不接 Mem0/Zep，不做跨会话自动回忆、用户画像或把助手结论写回知识库。

## 8. 外部研究与 MCP

### 8.1 网页搜索

AI Elements 的网页搜索按钮负责界面和用户选项；真正的搜索由后端工具提供，组件不附赠搜索索引或免费搜索服务。[AI Elements 聊天示例](https://elements.ai-sdk.dev/examples/chatbot)

P0 选 Gateway 内置 gateway.tools.perplexitySearch()，支持配合不同提供方模型，包括 Qwen。不再接 Tavily，当前每次 $0.005，通过 Gateway 计费并与 Token 分列。[Gateway 网页搜索](https://vercel.com/docs/ai-gateway/models-and-providers/web-search)

- 默认最多返回 5 条候选，总摘录约 6K tokens；优先官方域名与目标版本。
- 搜索摘要用于找 URL，URL Fetch 读取正文后再作为正式证据；拿不到足够证据则未验证。
- Official Documentation Tool 是技术实体/版本到官方域名和仓库的映射，加受控搜索和读取。
- 输入框提供联网开关并默认关闭；用户为本次 Run 主动开启后，后端仍须通过公开性与最小外发检查才注册外部研究工具。
- 只有用户目标确实需要外部核验、联网已开启、对象能确认是公开实体且查询不含私人信息时才注册搜索工具。内部项目、个人信息和无法确认公开性的实体禁止自动联网，只做本地分析并标记外部证据未验证。
- 外部研究作为独立步骤，只携带用户问题、必要实体/版本和待核验的公开声明，不携带完整笔记摘录或完整会话历史。
- Gateway 内置搜索是供应方执行工具，不冒充 MCP，也不依赖应用本地 tool approval 做执行前拦截；是否注册工具及其最小上下文由服务器在模型调用前决定。D1 验证实际事件、参数约束、取消和费用；平台内部不可观测步骤不伪造 Trace。
- P0 的 URL Fetch 只读取 Official Documentation Tool 映射或搜索结果中已确认的官方域名，不提供任意 URL 输入；同时拒绝私网地址、云元数据、DNS 重绑定和跨域重定向，限制协议、体积与时长，不执行网页脚本。

### 8.2 MCP 范围

1. 自建 Vault MCP Server：P0 只暴露 search_notes、read_note。线上与 Docker 本地都使用同仓库的 Streamable HTTP Route Handler，复用领域代码；stdio 和更多图关系工具放入 P1。
2. GitHub 官方只读 MCP：整体进入 P1。后续只读取公开仓库文件与 Release，使用远程 Streamable HTTP 的只读模式和精确工具白名单，服务端凭据不得拥有私人仓库访问权。[官方配置](https://github.com/github/github-mcp-server/blob/main/docs/server-configuration.md)

- 实际经过 MCP 初始化、发现、调用、结构化结果，记录 Server、工具和协议。
- Vault HTTP 凭据短期有效、绑定 Run/用户/知识范围；不接受模型自报 owner_id，不依赖函数内存维持长期会话。
- MCP Client Gateway 是应用内模块，不额外部署一个服务。
- P1 外部 MCP 无私人文件挂载、数据库凭据或完整 Vault，只接收必要参数。
- P0 不把私人原文发送给外部 MCP；无法在不携带私人内容的情况下完成时直接标记未验证。逐次确认外发原文的交互放入 P1。
- 网页、笔记和工具结果均是不可信数据，不能增加权限。
- 不允许访客填写任意 MCP URL，不注册笔记写入、Shell 或代码执行工具。
- 外部不可达时输出未验证；普通 HTTP 抓取不标成成功 MCP 调用。

## 9. 数据隔离、上传与保留

| 项目 | 本地版 | 公开免费体验站 |
|---|---|---|
| 所有者 | 持久本地 Owner | 匿名 Visitor |
| 知识库/会话保留 | 默认永久，用户删除 | 私人数据 24 小时 |
| 文件存储 | 用户机器持久卷 | Vercel 私有 Blob |
| 默认数据 | 我的知识库为空 | 只读示例数据 |
| 服务配额 | 用户配置 | 遵守免费托管资源与付费模型预算 |

初始公开上传限制按 Visitor 计算：单文件 15 MB、单批总计 25 MB、ZIP/Office 解压总计 50 MB、最多 50 个文件、PDF 累计 100 页、单个 XLSX 最多 20 个 Sheet 和 20,000 个非空单元格、解析后最多 2,000 个 chunk；全站同时保留的私人文件最多 250 个、私人 chunk 最多 10,000 个。每批最多分析 5 张图片或 PDF 页面，未分析部分仍可保存和预览。D7 用真实样本调整这些配置；本地保留资源安全上限但允许用户配置。

- Visitor ID 由服务端生成高熵随机值并写入安全 Cookie；会话 ID 不作为授权依据。无 Cookie 或 Cookie 过期时不能找回旧空间，旧数据仍按原 expires_at 清理。
- 写请求校验来源并限制 Visitor 创建、上传授权、排队任务及调用频率；浏览器 Cookie 只能标识 Visitor，实际所属关系由服务端查询确认。
- 拒绝路径穿越、符号链接、嵌套/加密 ZIP；解压时检查真实大小。
- 默认跳过 .git、.obsidian、隐藏配置和已知密钥文件，不执行上传内容。
- 正常多文件上传同样检查 MIME、扩展名、路径、真实大小及所属导入任务。
- 会话、文件、向量、报告、Trace 每次读取都鉴权；检索前做所属用户过滤。
- 受限 DB 角色与 RLS 做第二层保护；连接池事务内设置身份，不能泄漏身份上下文。
- 私人响应不进入共享缓存；文件读取经过鉴权，PDF 支持流式/Range。
- 删除先撤销访问、取消相关任务，再清理原文件、索引、派生结果与含内容日志。
- 公开模式 Workflow 按 expires_at 清理，每日 Cron 对账；过期校验实时生效，不等待物理删除。
- 本地清理器默认只删除临时文件/失败残留，不扫描删除正常个人知识库。
- 备份、WAL、第三方服务留存单独说明，不承诺物理介质立即擦除。
- 密钥仅服务端保存，在线站不接受任意供应商 URL；本地配置也必须明确可信接收方。

## 10. Trace、质量监测与评测

### 10.1 仅所有者可见的监测与离线评测

管理页面不出现在访客导航和 sitemap 中；隐藏地址之外必须有服务端认证。

- /admin 采用 Auth.js GitHub OAuth，只允许配置的不可变 GitHub 用户 ID。
- 页面、Server Action、API 和导出都检查 owner 权限；直接请求 URL 也拒绝，不能只隐藏按钮。
- 管理员 Cookie 使用 HttpOnly、Secure、合理到期；认证 Secret 和所有者白名单只保存在服务端。
- 访客只查看本人 Run 的公开过程、引用和报告，不能查看全站数据。
- 不提供公开 /quality 页。README 可以发布脱敏评测快照；在线监测只有所有者能看。

P0 只做一个服务端渲染的所有者页面：主表列出时间、Run、模式、状态、排队/运行耗时、模型与工具调用、估算费用和首个错误；点击后查看事件、引用、重试、检索/rerank 顺序及版本。页首按需计算最近 24 小时的完成/失败数、p50/p95、总费用、队列和清理积压，不做实时刷新或趋势图。

Trace 保留 model_id、provider、Prompt/工具/解析器/索引版本、deployment_id 与时间。费用未知显示待对账；Token 实际值、费用估算、平台账单分开。

P0 评测不用再建设在线标注系统。`evals/` 中保存版本化的 Demo Vault、问题、固定资料快照、预期证据、相关性等级、引用/问题判断、rubric 和开发集/留出集；执行脚本输出带配置版本、分子分母、失败原因和时间的 JSON 与 Markdown 报告。人工直接审查这些小型数据文件，在线标注编辑器进入 P1。

**召回率依赖标准答案，不能仅凭线上日志自动知道。** Recall@K = 召回的相关证据数 / 标注的全部相关证据数。无标注的线上任务显示“未评测”，不显示 0 或模型猜测的分数。仅标注候选池时注明“基于已标注池”，不能声称全库真实召回率；文档级、块级分开，允许等价证据集合。

- 显示样本量、标注覆盖比例、数据集版本和评分来源：确定性规则、人工、模型评审。
- 如使用模型评审，只把它作为建议并由人工抽检，不直接替代标准答案或人工结论。
- 默认只长期保存脱敏聚合运行数据。私人正文与含内容 Trace 随 Visitor TTL 删除，不自动加入长期评测集。
- P0 标注集只使用 Demo 与所有者主动加入的资料，不保留访客样本。
- AI SDK DevTools 仅用于本地开发。Vercel/Gateway 控制台辅助排障；P0 自有管理页和静态评测报告不依赖付费观测产品。
- P0 做运行表格、详情、版本化评测文件与静态报告；在线标注、趋势图、复杂告警、自动造题和全站实时重评延后。


### 10.2 评测目标

以下是发布目标，不是实测成绩或对所有资料的质量承诺；选定模型不达标时必须修复、收缩范围或依据评测更换模型。

| 指标 | 验收目标 |
|---|---|
| 检索 | Precision@5 ≥ 0.70、Recall@10 ≥ 0.85 |
| rerank | 比较关闭/开启后的 nDCG@10、引用支持和延迟，不预设一定提升 |
| 引用 | 位置测试全部通过；人工标注引用支持准确率 ≥ 95% |
| 问题发现 | 结构问题 Precision/Recall ≥ 95%；语义问题优先 Precision ≥ 80% |
| 外部来源 | 检查一手来源、版本匹配、证据直接性及独立性 |
| Task Success | 留出集满足 rubric 且无关键无依据结论，目标 ≥ 80% |
| 工具 | 首次与重试后错误分别统计，包含 rerank 与配额错误 |
| 效率 | 轮次、工具数、Token、配额消耗、运行时间和排队时间 |

## 13. 交付目录与配置

关键配置：

- APP_MODE：local 或 public-demo，决定 Owner/Visitor 和数据保留规则。
- DATABASE_URL：线上 Neon、本地 PostgreSQL；STORAGE_PROVIDER：blob 或 filesystem；DATA_DIR 为本地私有卷。
- BLOB_READ_WRITE_TOKEN；本地 WORKFLOW_TARGET_WORLD=@workflow/world-postgres 和 WORKFLOW_POSTGRES_URL，按锁定版本文档校验。
- AI_GATEWAY_API_KEY；主模型 alibaba/qwen3.7-flash、Embedding alibaba/qwen3-embedding-0.6b、rerank voyage/rerank-2.5-lite。
- HOSTING_FREE_ONLY=true；模型每日与单任务美元预算，供应商路由和价格档位配置。
- Gateway 同时承担模型与内置搜索凭据；AUTH_SECRET、管理登录使用的 GitHub OAuth client ID/secret、OWNER_GITHUB_ID、CRON_SECRET 全部服务端保存。P1 启用 GitHub MCP 时再加入独立的最小权限凭据。
- Preview 与 Production 数据库/存储和密钥隔离；私人配置不使用 NEXT_PUBLIC_ 前缀。
- 私人上传 TTL、文件额度、Run 并发、工具/模型调用预算。
- Visitor/全站待处理任务上限、解析后 chunk 上限、图片像素上限、排队/运行时限。
- 本地管理员初始化与公开站管理员认证分别配置。

CI 执行 lint、类型检查、确定性测试和构建。付费评测必须显式启用，不向不可信 PR 暴露密钥。开源交付包括许可证、素材来源、支持矩阵、免费资源限制、评测、部署/重启/备份/删除说明。
