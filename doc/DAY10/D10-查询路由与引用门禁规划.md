# DAY10：查询路由与工具解耦

状态：已完成结构化查询路由、初始检索复用、工具目录拆分和一次补搜门禁；尚未完成
多轮历史、主动取消、跨进程恢复和真实模型三路回归。

## 本次实现

- 新增结构化查询路由，模型只返回 `direct / retrieve / agent` 和一条受限查询文本。
  路由器不接收知识库正文，也不能直接授予工具权限。
- `direct` 只执行最终文本生成；`retrieve` 由服务器直接完成一次混合检索、来源读取
  和最终回答；只有 `agent` 启动 `ToolLoopAgent`。
- `agent` 复用服务器初始检索候选，不再强制首次调用 `search_notes`。初始候选存在时
  必须先调用 `read_sources`；无候选或已读取证据后才允许一次补充搜索。
- 删除名不副实的 `find_related`。新增 `expand_context`，围绕已读取证据确定性读取
  同一文件版本的前后相邻 Chunk，不生成 Embedding，也不执行 rerank。
- 工具按 `search-notes`、`read-sources`、`expand-context`、`finish-research` 独立文件
  组织，注册入口只负责组装；共享来源输出转换单独管理。
- Run 编排拆为公共入口、执行路径、过程流、最终回答、事件顺序、生命周期与类型，
  避免继续扩张单个 `runs.ts` 文件。
- 最终回答正文不再展示 `【编号】` 内联引用；来源仍以结构化数据保存并在回答下方
  展示。流式输出边界会确定性过滤跨增量拆分的纯数字引用标记，避免只依赖模型遵循提示。

## 服务端门禁

- `read_sources` 只能读取初始检索或补搜许可的 Chunk。
- `expand_context` 的锚点必须已经进入当前 Run 的引用集合。
- 补充搜索最多一次；存在未读初始候选时禁止提前补搜。
- 补搜返回新候选后，下一模型步骤强制先读取来源。
- 单次工具数量、单次读取数量和单 Chunk 正文长度继续受现有预算限制。
- 检索无候选时使用确定性“证据不足”回答，不让最终模型脱离资料猜测。
