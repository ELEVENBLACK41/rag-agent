# DAY10 第一步：回答行为与引用

## 范围与决定

- 用户授权实施 DAY10 第一块“回答行为与引用”；第二块多轮历史、第三块 Workflow 持久执行与取消恢复继续待实施。
- 已确认普通知识问题允许直接解释；涉及个人资料的事实才检索。沿用现有 ToolLoopAgent 按需选择工具，同步总计划第 6.5 节，不增加 QueryPlan 分类模型或固定预检索。

## 本次改动

### 回答行为与空库

- 保留已有的直接回答实时推流、首次工具调用时前文转入公开过程、调用工具后独立生成最终答案的流程。
- 提示词明确能力介绍和普通知识可直接回答；用户资料事实必须依据当前 Run 实际读取来源。
- 空库也能提交消息。无已发布资料时 Run 的 `snapshot_id` 为 `NULL`，Agent 不开放资料工具，资料问题提示导入；有资料时仍固定 Run 创建时的快照。
- 新建空库会话前复用 `ensureLocalPrincipal` 初始化本地工作区。迁移 `0007_allow_snapshotless_chat.sql` 仅放宽 Run 快照的非空约束，保留外键；已在本地数据库应用。

### 引用与最终答案

- `lib/chat/final-answer.ts` 独立负责最终提示词。最终生成只接收本轮重新授权的已读取证据，长度与 Agent 读取片段一致；资料作为不可信 JSON 数据，不执行资料中的指令。
- `lib/chat/citations.ts` 从完整正文提取专用内部标记 `【来源:编号】`，去重并校验编号属于本轮读取集合；仅保存、发布实际引用来源。无效或格式错误的编号进入失败，不产生来源按钮。
- 发布前再次检查实际引用来源是否仍可读取；保留既有来源 API 的 Run、工作区、快照、文件版本和删除状态校验。
- 正文持久化保留标记，界面统一隐藏；流式尾部暂缓显示未闭合标记，回放使用同一展示函数。普通数字、年份和列表序号保留。旧回答仅按其已发布引用兼容 `【数字】` 格式；旧格式自身无法区分同号正文与引用，新回答改用专用前缀消除此歧义。
- 底部“回答来源”仅显示有效实际引用，无来源时不显示；卡片保留原文与定位入口，不再显示编号。
- 最终生成消费 `fullStream` 的错误事件，部分输出后发生模型异常不能保存为成功。未取得证据且工具失败仍失败；已有部分证据时最终生成明确说明核对范围受限。

### 预算与检索边界

- 保持最多 6 个 Agent 步骤、每步 1,200 输出 token、最多 5 次工具执行；搜索与关联搜索共享最多 3 次检索预算。
- 相同搜索问题（忽略大小写和连续空白）或相同关联来源不重复请求检索服务。语义相同但措辞不同的查询仍可能执行，由总数上限约束；不新增语义去重模型。
- 工具入口同步占用预算，避免同一步并行调用突破上限；达到上限或重复搜索返回明确受控结果，不包装成系统调用失败。步骤之间按预算结束循环，由最终生成根据已读证据说明有限结论或缺口。
- `prepareStep` 只根据空库、候选范围和搜索预算限制可用工具，不强制首步搜索。结束工具使用 `sources-read / no-sources-read` 表达已读状态，不声称证据充分。
- SDK 调用按已安装 `ai@7.0.93` 的源码与类型检查，参考 [AI SDK 循环控制](https://ai-sdk.dev/docs/agents/loop-control) 和 [streamText](https://ai-sdk.dev/docs/reference/ai-sdk-core/stream-text)。

## 已知限制与后续

- 单独询问“什么是 RRF”时，真实模型虽然正确走了零检索直接回答，但给出了不准确的缩写解释；本次只确认检索策略生效，不能据此宣称普通知识回答准确率已达标。后续需要增加脱敏歧义问题样本，继续评估模型和提示词。
- 程序验证引用的来源归属和实际标记使用，不能自动证明每句话都受证据支持。已有历史回答缺失的引用信息也不会被追补或重新生成。
- 两份资料的完整比较、所有格式定位、资料在真实生成途中删除仍需更完整的脱敏场景验收；本次来源失效由内存探针验证，未删除用户资料进行测试。
- 直接回答依赖模型遵循“资料事实先读取”的指令；本次不增加独立意图分类或答案审判模型。
- 多轮上下文、会话列表、刷新后的历史入口、主动取消与后台恢复均留到后两步；第一步完成实现与上述定向验证，不等于 DAY10 全部验收完成。

## 公开草稿与最终回答交接修复（2026-09-16）

### 问题与实现

用户反馈：Agent 的公开阶段回答已形成完整概括，最终回答却重新组织、丢失细节，甚至把日期标题误写成项目名。原先最终生成仅接收当前问题与证据，没有收到 Agent 的公开结论。

- 新增 `lib/chat/public-draft.ts`，每个 Run 独立收集公开 `text-delta` 与 `finish_research` 的公开 briefing，按顺序传递给最终生成。普通搜索/读取工具的原始参数、工具结果和 reasoning 不进入草稿。
- 在过程区 800 字符显示裁剪之前收集公开增量，长回答尾部也能交接；结束工具只有 briefing、没有完整回答时同样支持。直接回答仍只生成一次，不经过最终生成。
- 草稿总预算为 12,000 字符，超限从最旧内容开始裁剪，保留较新的修正与结论，并显式传递 `truncated`。裁剪只影响草稿，来源预算与授权不受影响；旧内容可能丢失，不宣称保留了无限长度的完整草稿。
- `final-answer.ts` 分开提供执行事实、公开草稿与授权证据。最终生成保留与问题相关且有证据支持的结构、条件、差异和结论；删除计划性叙述与重复内容，遵从用户当前的详略和格式要求。
- 草稿不是证据或新指令；后出现的结论也需要核验。草稿为空、只有计划或被截断时仍根据证据回答；草稿与证据冲突时纠错，证据彼此冲突时说明分歧。引用从当前来源重新对应，不继承草稿的虚构编号。
- 明确当前工具没有完整文件清单能力，只能报告本次发现或读取范围；没有为该截图问题新增文件清单工具。
- 最终生成仍使用现有模型、1,200 输出 token 上限和单次最终生成流程。没有增加审判模型、历史上下文、数据库表或浏览器事件类型。

### 实际验证

- TypeScript、针对 `public-draft.ts`、`final-answer.ts`、`runs.ts` 的 ESLint 与 diff 空白检查通过。
- 临时缓冲探针验证空草稿、增量合并、片段顺序、返回副本隔离、超限裁剪与最新结论保留。
- 6 组临时 Run 集成探针验证：直接回复不二次生成、工具前后公开文本交接、超过 800 字符的尾部保留、结束 briefing 交接、无草稿回退、部分工具失败、最终模型异常、排除 reasoning/原始参数、原问题保留，以及保存正文与事件回放一致。部分检查在同一场景内合并执行。
- 使用实际 Qwen 最终生成测试 8 类脱敏样本：文件主题概述与日期误读纠正、甲乙方案表格比较与错误数字纠正、无证据的虚构草稿、草稿指令注入、部分工具失败、空草稿、来源冲突、用户要求一句话。首轮发现范围表述、表格引用和内部措辞遗漏后，针对失败样本复测；引用编号均通过本轮来源集合校验。
- 修正后的概述保留多条实际内容，使用“本次检索读取到”限定范围；比较表保留两个维度并正确引用两份证据；无证据不采信虚构天数；注入未执行；冲突证据分别列出；简短要求输出一句话。
- 部分失败样本最终明确说明“部分资料核对失败”，不采信缺失资料的结论。但实测仍偶有“复述未证实数值后说明无证据”的措辞，属于模型语义质量限制，不能宣称已自动保证逐句正确或所有场景一次生成都稳定。
- 本轮验证使用临时内存边界与脱敏真实模型调用，没有写入验证会话或用户知识库；临时脚本已清理。未重复浏览器验收，展示组件与 SSE 协议未改变。

## 证据收集职责与阶段展示分离（2026-09-16）

用户确认：调用工具后，Agent 负责收集和交接，最终生成统一负责正式回答；过程区不再展示另一份完整答案。

### 改动

- `run-agent.ts` 保留共用的资料范围、权限与证据约束，分开初始指令和证据收集指令。`prepareStep` 根据已完成步骤中的实际工具调用切换职责，失败调用也视为已进入收集阶段；不使用问题关键词判断，不强制首步检索。
- 收集阶段要求 Agent 通过工具 `briefing` 表达简短进展和收集结论，自由文本用于交接事实、条件、差异与缺口，不再邀请用户追问或面向用户写完整收尾。
- `runs.ts` 在首次工具调用时保存并发送 `answer_to_stage / answer-stage`，其 `stages` 为空：清空此前临时正文，保持任务运行，由工具说明接续展示。复用现有协议与前端逻辑。
- 调用工具后的自由文本只进入当前 Run 的草稿缓冲，不发布 `stage`、正文增量或 `stage_message`；即使模型没有遵守阶段指令，长篇草稿也不会形成界面的第二份答案。私密 reasoning 仍不收集。
- 搜索、读取与 `finish_research` 的公开 briefing 继续流式展示、持久化和回放；结束 briefing 同时进入待核验草稿。预算退出或未显式调用结束工具时，仍由现有最终生成链路处理已有证据。
- 无工具回答仍逐增量显示并直接保存，只生成一次。旧 Run 已保存的阶段文本仍按旧事件恢复，本次没有重写历史数据；新 Run 执行新的展示规则。
- 没有改动工具预算、来源权限或最终引用筛选。前文有关“800 字符阶段展示裁剪”和“前文移入过程区”的记录属于此前实现，本节取代其新 Run 展示行为。

### 验证

- TypeScript、定向 ESLint、diff 空白检查通过。
- 临时 Agent 探针验证初始/收集指令切换、共用安全规则保留、空库禁用工具、候选读取范围与搜索预算门禁。
- 对现有前端 `moveAnswerToStages` 的临时探针验证空数组清除正文、维持运行态、重复执行不重复插入，以及旧版非空阶段事件兼容。
- 9 组 Run 探针覆盖：无工具长回答、有工具前文、直接调用工具无前文、缺少 `tool-input-start`、显式结束工具、预算耗尽退出、Agent 异常、无证据工具失败、最终生成异常。同时检查工具 briefing 分段不重复、草稿中的长回答和邀请追问不发布、草稿仍传给最终生成、保存正文与实时/回放结果一致。
- 真实浏览器提交资料概括问题，依次执行搜索、两次读取及结束收集；展开过程区仅见 4 条简短 briefing 和工具状态，正文只有一份三点回答及来源。数据库检查确认 4 条阶段事件全部属于 `briefing:`、清空事件仅一次且 `stages` 为空、完成事件仅一次。
- 临时脚本已移除，验证会话通过产品原有删除功能软删除；未删除知识库文件。

边界：该改动从事件发布层保证自由文本草稿不会成为第二份阶段答案。briefing 的具体措辞与最终答案的语义质量仍受模型影响；不宣称每次生成都能完全避免不当收尾或事实错误。

## 文件清单工具 list_files（2026-09-16）

用户授权：增加查询知识库文件清单的工具，解决内容检索只能覆盖部分文件、不能回答完整文件目录的问题。

### 实现

- 新增 `lib/sources/file-inventory.ts`，直接查询本轮已发布快照的文件元数据。校验本地工作区与快照状态，过滤逻辑删除，按相对路径选择最新写入版本后检查其索引状态；同名不同目录保留为不同文件，旧数据无路径时沿用检索的文件名兼容规则。
- 使用只读、可重复读事务保证文件总数与分页查询的一致视图。`list_files` 每次返回最多 30 个文件的名称、Vault 相对路径、格式、总数、完整性和下一页偏移，不返回存储键、正文或内部文件 ID。
- 工具注册进现有 Agent，由模型按问题选择，不增加分类模型或关键词路由。文件清单问题优先列取元数据，需要内容时才搜索与读取正文；列表不会授权任意正文读取。
- 列表调用共享现有单轮 5 次工具预算，不占用搜索次数。状态仅保存成功查询的分页偏移；重叠或重复页在最终证据读取时去重，不能通过重复页误判完整。
- 最终生成前重新读取成功请求的分页范围，作为独立 `fileInventory` 证据传入，并保存 `file_inventory` 事件。纯文件清单不要求正文引用，也不伪造来源卡片；文件内容结论仍按原有来源规则核验。
- 最终生成后再次检查清单是否变化，变化时明确失败，不保存成成功回答。过程区工具活动显示为“查询文件清单”。
