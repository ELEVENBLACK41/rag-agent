# DAY10：聊天 RAG 收口实施计划

状态：待实施。本文是 `D10-查询路由与引用门禁规划.md` 的执行拆分；按顺序完成，每一项通过对应验证后再进入下一项。

## 目标与完成定义

DAY10 收口聊天 RAG 与其必要交互的五个问题：

1. 不需要知识库的问题不再检索。
2. 回答只发布正文实际使用、且属于当前 Run 固定快照的来源。
3. 只有确实需要多次检索和精读的复合问题，才进入本地只读 Agent 循环。
4. 一个 Run 的阶段回答和工具活动按真实事件展示，结束后折叠，最终答案始终独立展示。
5. 会话可在左侧新建、切换、重命名和删除；刷新后仍能恢复历史消息与未结束 Run。

完成后，普通对话保持轻量；单次知识问答继续复用已有混合检索；多步任务能够真实调用本地工具并在证据不足时正常结束。DAY10 不接入外网搜索、不新装 Agent 框架、不做通用工作流引擎，也不把聊天 UI 做成一套独立状态管理系统。

## 已有基础与边界

| 已有能力 | DAY10 的使用方式 |
| --- | --- |
| D8 混合检索、RRF 与 rerank | `retrieve` 与 `agent` 路由均先由服务端确定性复用；`search_notes` 仅用于 Agent 读证据后的二次定向检索。 |
| D9 Run、SSE、来源抽屉 | 继续作为事件与来源展示基础；不重做文件预览授权。 |
| `lib/agent/tools.ts` | 复用 `search_notes`、`read_sources`，并将无差异的 `find_related` 重构为受限上下文扩展与笔记链接跟随。 |
| `lib/agent/run-agent.ts` | 从当前未接入状态改为只由 `agent` 路由调用。 |

当前 `find_related` 只是“用已读正文再次检索”，候选与原混合检索基本相同，不能作为 Agent 的有效能力。本阶段将它替换为可验证的关系读取：Markdown Chunk 已保存 `sourceLocator.links`，逻辑文件已保存 Vault `sourcePath`，无需新增图数据库或重做导入主链路。

## 实施顺序

### 1. 查询路由

新增 `lib/chat/query-router.ts`，只维护稳定的 `QueryPlan`：

```ts
type QueryPlan = {
  route: "direct" | "retrieve" | "agent";
  searchQuery: string | null;
};
```

- 使用现有 AI SDK、Gateway 和 Zod 结构化输出，不新增路由框架或全局状态。
- 输入为当前问题与有限、已持久化的会话历史；历史仅用于补足“那第二页呢”这类省略主语问题。
- `direct` 用于问候、能力说明和需要澄清的问题；`retrieve` 用于常规资料问答；`agent` 只用于比较、交叉阅读或需要多次查找的复合任务。
- 路由失败时记录受限 Trace，并保守降级为 `retrieve`；不得伪装为 `direct` 成功。

验收：`你好` 不触发检索；“这份 PDF 讲什么”进入 `retrieve`；“比较两份笔记的方案差异并说明证据”可进入 `agent`。

### 2. 直接回答与引用门禁

调整 `lib/chat/runs.ts`，明确分离内部候选与用户可见引用：

- `retrievalCandidates` 只用于模型上下文和受限 Trace，不能直接传给前端。
- 模型回答中的 `【n】` 是唯一的候选发布入口；服务端提取编号后，以本 Run、固定快照和候选白名单校验。
- 校验通过的 `answerCitations` 才写入助手消息及 `run_completed` / SSE 完成事件。
- `direct` 固定写入空引用数组；无足够证据的回答允许发布空数组并明确说明限制。
- 不存在、重复或越权的编号按生成错误处理，绝不创建伪引用。

验收：检索得到 8 个候选、回答用了 2 个时，页面和持久化只出现 2 个可打开来源；普通问候没有来源按钮。

### 3. 工具重构与受限 Agent 循环

先在 `lib/agent/tools.ts` 完成最小工具重构，再在路由为 `agent` 时调用 `createVaultRunAgent`。工具必须提供一次混合检索之外的新证据读取能力：

- `agent` 路由先由服务端使用 `QueryPlan.searchQuery` 执行一次初始混合检索，持久化 Trace 并把受限候选目录写入当前 Run State。初始检索不是 Agent 工具调用，避免模型为同一检索多做一次无价值决策。
- 保留 `read_sources`：Agent 根据初始候选目录选择少量 Chunk 读取；它只读取本轮已获授权的 Chunk，并生成最终可用的引用编号。这是 Agent 的证据读取边界。
- 保留 `search_notes`，但不再强制首步调用：只有 Agent 已读证据后发现缺口，需要以更具体的关键词补充检索时才允许调用。它仍只检索当前固定快照并返回受限候选标识与定位信息。
- 新增 `expand_source_context`：输入一个已读 Chunk，只返回同一文件、同一固定快照内相邻的有限 Chunk 或同标题范围。它用于补足命中片段的上下文，禁止读取整篇文件。
- 将当前 `find_related` 改为 `follow_note_links`：输入已读 Markdown Chunk，在当前固定快照中按 `sourceLocator.links` 和 `logical_files.sourcePath` 解析链接目标；只返回实际存在、可读取的目标 Chunk。非 Markdown 或不存在/歧义链接明确返回无结果，不能回退为全文搜索伪装成功。
- Agent 的默认链路是“服务端初始检索 → `read_sources` → `expand_source_context` / `follow_note_links` → `read_sources` → 最终回答”。只有发现证据缺口时才插入 `search_notes` 做二次定向检索。工具不强制每轮都调用；一轮检索即可回答的问题应留在 `retrieve` 路由。
- 最终结论只可依据 `read_sources` 已返回的证据；上下文扩展和链接跟随只是发现或补读入口。
- 限制最大步骤数、单次读取来源数量、正文长度与输出 token，复用已有常量，不新增第二套预算配置。
- 运行过程只记录和展示阶段说明、工具开始/结束、受限结果摘要与失败；不保存或显示模型私密 reasoning。
- 至少支持“已找到足够证据并完成”和“本地证据不足，返回部分完成”两种正常退出。

验收：复合问题的初始检索只执行一次且不产生 Agent 工具调用；随后至少真实完成一次“读取来源 → 扩展同文上下文”或“读取来源 → 跟随 Obsidian 链接 → 读取目标”的链路。只有证据缺口场景才允许出现二次 `search_notes`；无证据时返回部分完成，不将相似但不支持结论的片段作为引用。

### 4. Run 过程 UI

将当前散落在 `vault-workspace.tsx` 的阶段文案、工具状态和最终消息，按各自职责拆开：

- 新增 `components/chat/agent-process.tsx`，只渲染同一 Run 的公开事件：阶段回答、工具开始/完成/失败和恢复提示。
- 运行中过程区默认展开；完成、部分完成、失败或取消后折叠为用时/状态标题。最终回答或部分完成报告始终位于过程区外，且一轮只有一个。
- 按服务端 `sequence` 顺序渲染事件，不能在结束后补造“思考过程”；不传递模型 reasoning、完整工具参数或原始正文。
- `vault-workspace.tsx` 只保留页面组合；SSE 消费、临时消息和恢复逻辑移入一个有独立异步职责的 Hook，避免继续堆积在页面组件。
- 继续复用已安装的 AI Elements `Conversation`、`MessageResponse`；按需引入 `ChainOfThought` 和 `Tool`，不整库安装组件。

验收：Agent 的阶段文字先出现、工具事件随后出现；完成后过程折叠而最终答案仍可见；刷新后事件顺序和最终答案均不重复。

### 5. 多会话、取消与恢复收口

只补齐聊天实际依赖的最小会话与 Run 生命周期，不提前建设通用任务平台：

- 增加会话列表、会话详情和重命名的服务端读取/写入边界；左侧栏提供新建、历史会话切换、标题搜索、重命名和删除。首条问题仍作为默认标题，不增加模型自动命名。
- 使用 `/` 作为新会话入口、`/chat/[id]` 作为已保存会话入口；页面只负责加载和组合，不复制两套聊天界面。
- 当前会话、消息和 Run 均从服务端读取；切换会话不能复用上一会话的临时消息、引用或来源抽屉状态。
- Run 保存路由结果与改写后的检索问题，历史刷新后可追踪本轮决策；路由完成、工具结果和最终写入是明确检查点。
- 使用有限历史生成检索问题，不能把整段会话无限放入模型上下文。
- 停止生成必须调用服务端取消，而非仅中断浏览器 `fetch`；取消状态持久化后，后续工具或最终写入必须拒绝覆盖为成功。关闭页面本身不取消任务。
- SSE 重连按已有单调事件序号补齐；服务端从已持久化检查点恢复或明确失败，不重复最终正文、工具事件或完成事件。
- 失败、取消与部分完成保留已验证证据，不能被后续写入覆盖成成功。

验收：左侧可切换两个历史会话且消息、引用互不串扰；生成中断后刷新不出现双重最终答案；“那第二页呢”可结合上一轮资料范围检索；停止生成后 Run 不得重新完成；失败 Run 不显示完成状态。

## 不做清单

- 不让所有消息都进入 Agent，也不让 Agent 替代稳定的单次 RAG。
- 不接入 Gateway Search/Fetch；本地证据不足由 D12 按用户许可处理。
- 不做第二次模型引用核验；首版先以编号白名单、Run 与快照归属校验保证真实性。
- 不将工具调用、候选正文、模型 reasoning 原样输出给浏览器。
- 不读取无界完整文档；`expand_source_context` 必须带 Chunk 与字符上限。
- 不预建图数据库、通用关系引擎或跨格式伪链接；`follow_note_links` 只支持已存储的 Markdown 内部链接。
- 不把跨文档对比伪装为工具；模型基于实际读到的多个来源完成对比。

## 每项完成后的检查

每完成一个实施项，只执行与改动相关的类型检查、聊天/RAG 定向检查和 `git diff --check`。全部完成后再集中运行以下回归：

- `direct`、`retrieve`、`agent` 各至少一个真实用例。
- 无答案、伪引用编号、有限历史追问、Agent 证据不足。
- 同一文档命中片段的上下文扩展，以及 Markdown 链接目标跟随；验证不会越出 Run 固定快照。
- 两个历史会话的切换、重命名、删除和标题搜索；确认消息、引用和抽屉状态不串扰。
- 阶段回答与工具事件的实时顺序、完成后折叠，以及唯一最终回答。
- 一次停止生成、一次生成中断或 SSE 重连，确认最终消息与事件不重复且终态正确。
- D9 跨格式真实资料链路：提问 → 检索 → 回答 → 点击引用 → 正确定位。

未完成以上回归前，DAY10 只能标记为“代码完成，待验收”，不能冻结聊天/RAG 范围。
