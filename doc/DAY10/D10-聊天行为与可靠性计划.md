# DAY10：让聊天正常回答、连续对话、可靠恢复

状态：第一步“回答行为与引用”、第二步“多轮会话与历史”和第三步“取消、恢复与验证”均已实现并由用户完成验收；对应实施与实际验证见同目录记录。DAY10 已收口，后续改动进入新的阶段记录。

## 目标与方案

在现有导入、混合检索和 ToolLoopAgent 基础上，让普通对话正常结束，让知识库回答有依据，并补齐多轮会话与中断恢复。

建议继续由现有 Agent 自动选择工具，不新增独立意图分类模型，不拆成三套执行链路。服务端负责来源权限、引用有效性、预算和任务状态；模型负责判断是否需要检索及如何组织回答。

第一步已按用户授权采用现有 Agent 按需选择工具，不增加 `direct / retrieve / agent` 分类模型或服务端固定预检索；总计划第 6.5 节同步此项决定。

## 一、回答行为与引用

- 同时调整 Agent 提示词、工具说明和最终回答条件：问候、致谢、能力介绍可以直接回复；涉及用户知识库事实时，必须读取受权资料后作答。
- 检索判断由当前 Agent 结合用户问题、最近对话和明确的资料范围完成，不用关键词硬匹配：问候和仅改写已有回答通常无需检索；明确询问“我的笔记”“这份文档”或比较资料时需要检索；资料指代确实不清时再澄清。模型判断可能出错，用误检索和漏检索样本验收，服务端继续约束资料访问范围。
- 保留公开执行过程与唯一最终答案的展示方式。首次工具调用前的文本实时推送到回答区，但不提前标记任务完成；一旦调用工具，通过归类事件清空临时正文，过程区只展示工具 briefing 和状态。Agent 自由文本保留为待核验草稿，不再展示为阶段长回答；未调用工具则直接保存回答，调用工具后沿用独立最终生成方式。
- 区分三种结果：无需资料即可回答、检索后证据不足、系统调用失败。前两种可以没有引用；只有实际异常显示执行失败。证据不足时说明“本次未找到支持”，不能断言知识库绝对不存在相关内容。
- 区分搜索候选、实际读取来源和答案实际引用。仅发布正文使用且属于当前 Run 固定快照、已读取来源集合的引用；无效编号不能变成来源按钮。程序校验来源归属，不宣称已经自动证明每句话都被证据支持。
- 正文不生成或嵌入来源编号；最终生成以独立的 `answer` 与 `citationIds` 字段分别返回正文和实际使用的来源。服务端校验来源归属后在下方展示“回答来源”卡片，点击仍能打开原文和定位；不从正文解析引用，也不将全部读取来源自动作为回答来源。新事件明确标记纯正文，旧事件回放兼容历史标记；普通数字及字面括号内容保持原样，无来源时不显示该区域。
- 复用现有搜索、读取和关联工具；限制重复搜索、总步骤和工具次数，预算耗尽时根据已有证据给出有限结论或不足说明。已检索不等于已读证据，已读证据也不等于问题全部解决。
- 空知识库仍允许问候和能力介绍；涉及知识库时提示导入资料。需要检索的 Run 固定资料快照，旧会话内容不能代替本轮来源授权。

## 二、多轮会话与历史

- 接通会话列表、打开历史会话和新建会话；刷新后恢复已保存的消息、来源和执行过程，复用现有删除能力。
- 同一会话共享对话上下文，不同会话默认隔离。服务端为 Agent 和最终回答生成器组装当前问题与最近完整对话，不能只传本次问题；刷新或重新打开会话后也能继续追问。
- “上面第二点”等最近对话指代应直接承接，不要求用户重复说明。长会话按上下文预算保留最近完整问答及当前明确约束；数据库保存全部历史，不等于每轮全部发送。仅在裁剪后缺少必要信息或存在真实歧义时澄清，不假装记得未提供的旧内容。本阶段不新增自动摘要或历史检索工具。
- 历史用于理解追问，不能把助手以前的回答当作新的知识库证据。资料更新后，新 Run 使用最新快照，旧 Run 保留原快照引用；需要引用资料事实时按本次范围读取，旧来源不可用时明确提示。
- 按职责将聊天异步状态与消息展示从工作台中拆出，保持页面入口轻量；复用现有组件，不新增状态库或记忆服务。

## 三、取消、恢复与验证

- 浏览器断线与主动停止分开处理：断线后后台任务可继续，重连按事件序号补齐；主动停止由服务端记录取消并中止可中止的模型请求、阻止后续工具与终态写回，不能只停止浏览器接收。
- 聊天执行接入现有 Workflow 能力，持久保存必要步骤状态；不能仅凭 SSE 事件能回放就宣称任务能恢复。复用当前技术栈，不引入第二套队列。
- 事件先保存再发送，恢复时按序去重；最终答案、Run 终态与完成事件一致提交。取消或删除后，旧执行不能把任务重新标记为完成。
- 最终答案已经输出一部分时，不自动重生成并拼接另一份答案。失败保留未完成标记，用户主动重试创建新尝试并明确替换显示；模型请求不承诺恰好执行一次。
- 用少量脱敏问题完成下表回归，并记录类型检查、必要构建及真实浏览器/服务端结果。先核实并重新生成当前回退后残留的 Next.js 路由类型，再判断代码是否存在类型错误。

## 验收清单

| 场景 | 通过标准 |
| --- | --- |
| 空库或有资料时发送“你好”“谢谢” | 零检索调用，正常输出并保存最终回答，无来源按钮 |
| 询问资料中的具体事实 | 真实搜索和读取；正文无来源编号，底部仅显示实际引用且校验通过的来源，点击可定位 |
| 比较两份资料 | 按需要执行多步读取；缺少一份资料时说明比较范围与缺口 |
| 询问资料没有支持的问题 | 正常说明证据不足，不伪造答案，不显示系统执行失败 |
| 同一会话追问“上面第二点是什么意思” | 携带上一轮完整问答，直接解释对应内容；刷新并重新打开后仍能承接 |
| 长会话或切换会话 | 长会话受预算限制，真实缺失或歧义时才澄清；新会话不带入其他会话历史 |
| 刷新、断网后重连 | 恢复同一会话和执行状态，无重复正文、重复最终答案 |
| 主动停止、失败后重试 | 服务端停止后续执行，旧尝试不覆盖新尝试，不拼接答案 |
| 执行中重启服务 | 从持久状态恢复或明确结束为失败，不悬挂、不伪装完成 |
| 资料删除、无效引用、旧快照 | 保持授权边界，失效来源明确提示；引用可用时能打开对应原文 |
