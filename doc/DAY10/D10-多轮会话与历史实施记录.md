# DAY10 第二阶段：多轮会话与历史

状态：第一阶段已由用户验收；本阶段已实现并完成以下验证，等待用户验收。第三阶段服务端取消、Workflow 持久执行和可靠重连尚未实施。

## 范围与实现

- Agent 和最终生成器使用同一份服务器组装的 `messages`：最近完整历史问答 + 当前问题。客户端只发送问题和会话 ID，不接受浏览器自填历史作为可信会话记录。
- 历史最多保留最近 8 轮、16,000 字符，当前问题不计入历史预算且始终完整保留。只按完整问答裁剪，不拆开一问一答；最新完整轮次超预算时不跳过它去拼更早历史。省略历史时明确告知模型，不假装记得未提供的内容。
- 只读取当前工作区、未删除会话、本轮之前已完成 Run 的问答；失败、运行中和当前轮不进入模型上下文。历史中保存的来源编号只用于旧显示兼容，不作为新 Run 的读取权限或新证据。新 Run 仍选择最新已发布快照。
- 新增会话列表 GET 和会话详情 GET，复用软删除接口；列表每页 30 个，历史每页 20 轮。历史按 Run 的数据库时间与 ID 游标向前加载，避免日期精度损失和新增消息导致偏移错位。
- 历史详情恢复用户消息、成功回答、来源卡片和公开执行过程；失败及未完成 Run 从事件恢复部分正文并如实标注状态，不将部分答案标为成功。执行中的快照在历史页面显示“未完成 · 状态待确认”，可手动刷新查看已保存进度。
- URL 只保存当前会话 ID，刷新及前进/后退时从受保护 API 恢复；不把私人正文存入 localStorage。支持新建、切换、加载更早消息、移动端历史抽屉和当前会话删除。
- 客户端用 AbortController 与请求序号隔离请求生命周期，切换后迟到的历史响应和旧流不能覆盖新会话。流式消息直接展示，正文与下方来源继续分开。
- Run 事件读取补齐了工作区与会话删除状态检查，其他工作区及已删除会话的事件不可读取。

## 实际验证

| 验证 | 结果 |
| --- | --- |
| PostgreSQL 临时事务 | 验证 23 轮历史分页、不同会话隔离、跨工作区拒绝、删除过滤、事件访问范围、完整问答裁剪、当前轮及失败/运行中轮次排除；验证旧正文编号与新字面 `【1】` 的不同处理、来源卡片和失败/未完成恢复。全部回滚，并确认测试会话未残留 |
| SSE 读取 | 中文、emoji 按字节拆分及 CRLF 帧均可完整还原 |
| 实际浏览器和模型 | 在临时会话提供“梧桐回归”代号，追问正确承接；刷新后恢复全部消息并继续修改代号成功 |
| 会话切换 | 新会话不知道上一会话代号；从侧栏重新打开旧会话恢复三轮消息；人为延迟旧请求后切换会话，没有被迟到响应覆盖 |
| 移动端与删除 | 390px 窄屏抽屉能选择历史并关闭；删除当前测试会话后回到新会话，旧详情 API 返回 404。首轮自动化未等待抽屉退场动画导致断言失败，补充等待后复测通过，无产品代码规避 |
| 历史来源 | 浏览器恢复旧来源卡片，点击确实请求其原 Run/Chunk；所选旧来源已失效，接口返回 404，抽屉正确展示不可用提示。本轮未以该案例宣称所有格式原文预览均重新验收 |
| 最终模型上下文 | 脱敏历史列出蓝、红两个项目后，追问“第二个项目”；实际 Qwen 最终生成正确回答红项目 8 月完成，仅返回当前来源编号 2 |
| 静态验证与构建 | 定向 ESLint、完整 TypeScript 和 `pnpm build` 通过。此前 `class-variance-authority` 类型错误实际来自沙箱依赖链接访问限制；沙箱外检查通过，没有重装依赖 |

真实浏览器测试只创建自己的临时会话，完成后使用产品原有软删除接口清理；不删除用户会话或知识库文件。数据库探针均在事务中回滚，临时脚本和截图随后清理。

## 限制与后续

### 会话路由统一（2026-09-16）

- 新会话统一使用 `/chat`，已有会话使用 `/chat/[conversationId]`；动态页面复用聊天页面组合，不重复实现工作台。
- 首页 `/` 跳转至 `/chat`；按用户决定不兼容旧的 `?conversation=` 链接，不再读取该参数。
- 会话创建、切换、新建、删除后的地址统一更新；刷新及浏览器前进/后退从路径恢复会话。知识库“返回聊天”入口改为 `/chat`。
- 保留原生 History API 更新地址，避免首轮流式回答获得会话 ID 时触发页面导航、卸载请求。
- 验证：`pnpm exec next typegen`、本次修改代码的 ESLint 检查及 `git diff --check` 通过；本地 HTTP 检查 `/` 返回 307 且指向 `/chat`，`/chat` 和用户提供的会话路径均返回 200。
- `pnpm exec tsc --noEmit` 未通过：已有 UI 文件无法解析 `class-variance-authority`，本轮未改动这些文件或安装依赖。未进行浏览器交互及真实模型调用验收。

- “停止”仍只停止浏览器接收，不能声称服务器任务已经取消；断线后台继续执行、自动重连、重启恢复和取消/删除与终态写回的并发保护属于第三阶段。
- 这是最近对话上下文，不是长期记忆；超预算的更早约束可能不可用。没有自动摘要或历史检索工具。
- 资料内容仍受模型生成质量影响；历史回答不能替代当前授权证据，也不保证所有省略指代都无歧义。
- 本轮只读诊断发现当前连接数据库的 `runs.snapshot_id` 仍保留非空约束，而仓库已有 `0007_allow_snapshotless_chat.sql` 放宽该约束。无任何已发布快照时创建首轮 Run 仍可能失败；本轮未改动迁移记录或数据库结构，测试使用事务内快照。这是现有数据库迁移状态问题，不将其记为新阶段已修复。
- 建议验收：新会话提问 → 连续追问 → 刷新后追问 → 切换会话确认隔离 → 返回旧会话查看来源/过程 → 删除会话。第三阶段另行授权实施。
