# 文件介绍提前结束修复

## 真实问题

用户先询问文件清单，随后要求详细介绍、简短概括文件，系统却称无法获取内容，直到用户追问原因才真正搜索并读取。

只读检查该会话持久事件确认：

- 详细介绍那轮只有 `list_files → finish_research`，没有正文搜索、读取或检索异常。
- 简短概括那轮没有工具调用，直接生成与上一轮类似的缺少正文说明。
- 后一轮确实取得正文，说明不能将前两轮问题归因为索引不存在。

## 修正

- 基础指令区分未尝试获取与实际尝试后无法获取；概括的长度要求不免除正文读取，历史中的失败说法不能代替本轮工具结果。
- 收集阶段及逐步控制明确按本轮目标判断：清单目标只需元数据；正文介绍需要搜索、读取，尚有适用工具时不能仅因未读正文就结束。
- 同步 list_files、search_notes 和 finish_research 描述，明确输入输出边界及结束条件。
- 保持现有 Agent 自动选择工具，没有增加关键词分类器、固定预检索、第二个决策模型或无界重试。工具权限和预算未放宽。

## 实际验证

使用项目实际 Qwen、Agent 装配、工具定义和预算状态，检索/文件读取以脱敏内存数据替代；不写会话或知识库，不向模型发送用户正文。

首轮发现清单问题多余搜索，调整目标范围说明后复验：

| 场景 | 结果 |
| --- | --- |
| 文件清单 | list_files → finish_research，无正文检索 |
| 详细介绍文件 | 最终执行搜索、读取并取得引用后交接 |
| 历史失败后要求简短概括 | search_notes → read_sources → finish_research |
| 问候 | 零工具调用 |
| 搜索无结果 | 执行搜索后有界结束，未伪造正文或引用 |

详细介绍样本曾先尝试尚未开放的 read_sources，随后纠正为搜索、读取并完成；不能宣称模型每一步均正确。此次修正加强提示和工具契约，不是服务端对所有自然语言任务的完成度证明。

定向 ESLint、完整 TypeScript 检查通过。模型探针验证工具选择，未通过新建用户会话验证整条最终生成流程；用户原有历史回答没有改写。临时脚本已清理。
