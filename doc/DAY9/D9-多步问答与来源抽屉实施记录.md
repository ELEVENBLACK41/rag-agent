# DAY9：受限多步问答与来源抽屉

状态：来源抽屉与受限多步问答已接通并完成真实 Run 验证。2026-09-15 根据最新决定恢复
ToolLoopAgent，本地证据链固定包含真实搜索、来源读取和证据收集结束步骤；AI 生成的公开
阶段说明与最终答案分区展示，不发布模型私密 reasoning。

> 2026-09-15 后续结构已由 DAY10 查询路由与工具解耦升级：初始检索改由服务器执行，
> `find_related` 已替换为不产生新向量查询的 `expand_context`。本文件保留 DAY9 验收历史。

## 实现范围

- 当前问答通过 AI SDK `ToolLoopAgent` 调用 `search_notes`、`read_sources`、可选的
  `find_related` 和 `finish_research`。第一步强制搜索；有候选但尚未读取时强制读取，
  防止模型跳过证据直接回答。
- 每个工具 Schema 要求模型生成不超过 200 字的 `briefing`，它作为公开阶段说明进入
  `stage_message`；工具参数、返回正文和 reasoning 不进入 UI 事件。
- Agent 只收集证据。完成后，系统根据实际读取的引用重新读取受权 Chunk，由独立
  `streamText` 生成最终回答，避免阶段性文本和最终结果拼接。
- 检索与 rerank 保存不含正文的排序 Trace；最终引用只取 `read_sources` 实际读取的
  Chunk，不再把所有检索候选都发布成引用。
- 前端使用 AI Elements `ChainOfThought` 按事件顺序展示 briefing 与工具状态：执行期间
  保持展开，第一段最终结果到达后默认折叠；最终答案继续使用 `MessageResponse`。
- 2026-09-15 将 `briefing` 的 `tool-input-delta` 和 Agent 公开 `text-delta` 转换为带
  `stageId` 的阶段增量；前端按同一标识合并并实时渲染。阶段文本使用无动画的
  `MessageResponse`，只有工具执行状态继续使用 `Shimmer`。
- 新增 `lib/sources/` 和三个来源 API：预览、原始文件、视觉派生图片。每次读取都从
  `Run → Snapshot → Chunk → FileVersion` 重建授权关系，前端没有存储键或 Blob URL。
- 聊天引用改为可点击按钮，使用 shadcn `Sheet` 作为右侧来源抽屉；PDF 原文件按
  物理页打开，视觉来源展示对应派生图片。
- 来源抽屉的小屏保持全宽；桌面端使用 `88vw`、最大 `1440px`。宽度类使用与 shadcn
  `SheetContent` 相同的 `data-side` 选择器，确保不会被默认 `sm:max-w-sm` 覆盖。

  生成中断替换与 SSE 断线补齐的完整交互归 D10。

  数据库级并发控制仍按 D10 的 Workflow/恢复范围实现。

  D10 仍需增加 `direct / retrieve / agent` 结构化查询路由、多轮历史与完整刷新恢复。
