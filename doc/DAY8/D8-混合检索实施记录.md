# DAY8：跨格式混合检索与 rerank

状态：已完成代码、静态校验和本地真实跨格式检索验证；完整的质量百分比仍须在
DAY16 使用扩充后的开发集与留出集计算，不能由少量 fixture 验证替代。

## 实现范围

- Markdown 改为标题路径、普通段落与 fenced code block 感知切块；代码内部的空行和 `#` 不再被当作文档结构。Chunk 正文包含完整标题路径和代码语言，原始定位保留在 `SourceLocator`。
- PDF 继续以物理页为绝对边界；DOCX 继续以标题路径、段落或基础表格定位；XLSX 继续以工作表与单元格区域定位。DAY8 不改变各格式已验证的文件解析范围。
- 新增中文关键词候选：不引入额外中文分词服务，采用完整中文短语、相邻双字词和拉丁/版本词的直接匹配，适用于当前 P0 有界 Chunk 规模。
- 新增向量候选、RRF 融合与 Gateway rerank。候选数、RRF 常数、超时和模型 ID 集中在 `lib/retrieval/config.ts`。
- 向量服务失败时保留关键词候选；rerank 超时、配额或服务失败时保留 RRF 前列。Trace 明确记录 `fallback` 与原因，不伪造成功。
- 聊天 Run 在生成前写入不含私人正文的 `retrieval_trace`：关键词、关键词/向量/RRF/最终 Chunk ID 顺序、实际参数、rerank 前后顺序或失败原因均可追溯。
- 新增首批人工标注的跨格式开发集，位置见 `evals/day8/retrieval-samples.json`；该数据集不用于质量宣称。

## 实际验证

| 检查项 | 结果 |
| --- | --- |
| TypeScript | 通过：`node_modules/.bin/tsc.cmd --noEmit`。 |
| 定向 ESLint | 通过：覆盖 DAY8 新增/修改的 retrieval、Markdown 和聊天编排文件。 |
| 生产构建 | 通过：`node_modules/.bin/next.cmd build`，包含 Next.js 路由与 13 个 Workflow Step 编译。 |
| Markdown/TXT 混合检索 | 通过：两份无敏感 fixture 导入、向量化后，问题命中 `vault-a.md` 的 Block ID `d4-vault-a`；关键词、向量、RRF 与 rerank 均在同一 Run Trace 中留痕。 |
| rerank Trace | 通过：`voyage/rerank-2.5-lite` 真实返回排序；一次 Markdown/TXT Run 耗时约 1.5 秒，XLSX Run 约 0.5 秒。Trace 保存 rerank 输入/输出 Chunk ID 与实际配置。 |
| PDF/DOCX/XLSX 混合检索 | 通过：三份 fixture 在同一候选快照完成导入。PDF 问答引用第 1 页；DOCX 问答引用 `tableIndex: 1`；XLSX 问答以 `Overview · A1:D4` 为第一引用，正确回答公式 `B2*C2` 的缓存值 `36`。 |
| 测试资料清理 | 通过：五份 DAY8 临时导入记录均通过删除接口标记为 `deleted`，未保留为当前可检索资料。 |

模型目录 HTTP 请求在当前环境未返回内容；以上真实运行已直接验证计划锁定的 Embedding、
rerank 模型均可被当前 Gateway 配置调用，但不将此一次连通性检查写成长期可用性保证。
