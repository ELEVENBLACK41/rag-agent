# D4 知识库管理页与版本优先实施记录

## 本次目标

- 将文件上传从聊天工作台移到独立的 `/library` 页面。
- 页面刷新后从数据库当前已发布快照恢复文件清单，不依赖浏览器内存状态。
- 展示文件版本号，并明确标记后续 AI Run 当前使用的版本。
- 修复早期无 `sourcePath` 数据与后续同名根目录文件可能同时进入检索的问题。

## 实施结果

- `GET /api/imports` 返回当前工作区最后一个已发布快照中的文件清单。
- 知识库页在首次进入、导入完成和删除完成后重新读取服务端清单。
- 文件行展示版本号、文件大小、更新时间、“AI 当前使用”和发布状态。
- 聊天入口只负责聊天组合，通过服务端当前快照决定输入框是否可用。
- 关键词检索和向量检索共享同一份快照内活跃文件版本集合。
- 检索和来源读取改为通过 `index_snapshot_files` 判断快照成员，不再错误要求 Chunk 的创建快照等于当前 Run 快照。

## 增量快照问题修复

`chunks.snapshot_id` 记录文件首次解析时所属的候选快照；发布后续增量快照时，系统继承的是 `file_version_id`，不会复制 Chunk。此前检索额外要求 `chunks.snapshot_id` 等于最新快照，导致只有最后一批上传文件能命中，继承文件虽然显示在知识库清单中却无法检索。

现在固定 Run 的资料范围以 `index_snapshot_files(snapshot_id, file_version_id)` 为唯一成员关系，Chunk 再通过 `file_version_id` 归属到文件。该规则同时应用于关键词检索、向量检索、Agent 来源读取和引用抽屉授权。

## 版本判定

同一 Vault 相对路径视为同一份资料。一个固定快照内若存在多条同路径记录，按文件版本写入时间选择最新记录；D3 旧数据缺少相对路径时使用文件名与后续根目录同名文件对齐。不同文件夹下有完整相对路径的同名文件仍保持独立。

这次没有修改旧快照或删除旧文件版本。历史 Run 继续绑定原快照，新的 Run 在自己的固定快照内只检索每个路径的最新记录。

## 当前限制

- 当前页面只展示 AI 使用的活跃版本，不提供历史版本浏览和回滚。
- 旧数据的同名对齐仅对缺少 `sourcePath` 的根目录历史记录生效；有完整相对路径的文件按路径区分。
