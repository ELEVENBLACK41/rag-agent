# D14：管理鉴权与运行观测

状态：第一轮基础实现与本地验证完成，尚未宣称 D14 全部指标和后续评测要求已验收；未部署线上。用户确认 D12 已验收，并决定跳过 D13，直接进入 D14。Vault MCP 不再作为当前版本前置或发布门禁。

## 已实现

- `/admin` 使用计划中的 Auth.js GitHub OAuth；只允许 `OWNER_GITHUB_ID` 指定的不可变用户 ID。每次访问重新检查白名单，缺少配置时保持关闭，没有本地绕过。JWT Session 有效期 8 小时，Cookie 使用 Auth.js 默认安全配置，正式环境应使用 HTTPS。
- 管理布局、各页面、数据读取函数与 Run JSON 导出接口均检查 owner。管理导航不加入访客侧栏，管理页面不允许搜索引擎索引；导出 `private, no-store`。
- 提供最近 1–720 小时和状态筛选、最多 100 个 Run 的有界列表、会话详情、Run 详情、当前配置、指标目录、导入资源统计和评测报告入口。样本截断、时间窗口与统计分母明确展示，当前不是无限历史分页。
- 新增 `run_observations`，配置、上下文、模型和工具观测独立于公开 SSE。记录以 Run + observation ID 唯一，同一回调重复完成不新增用量；配置首次写入后不可覆盖，取消、终态或会话删除后拒绝迟到写入。
- 实际执行前记录配置快照与 SHA-256；生成模型和 Token 上限统一读取聊天配置。五种文档解析器共用原本相同的 1400 字符预算，切块算法未改变；搜索摘要预算也由执行器与监控共用。
- 每个模型步骤记录输入/输出/总 Token、缓存读取/推理子项、返回模型、SDK provider、结束原因、指令哈希、模型响应和步骤耗时、SDK 本地工具耗时。provider 字段不是未经核验的实际路由供应商；不保存完整回调、请求正文或私密推理。
- 工具按真实 toolCallId 记录状态、可识别结果数量和应用接收事件间隔；SDK 工具执行耗时与该间隔分开。预算退出等领域状态保留在 resultStatus，不能把工具返回当作目标已经完成。
- 检索 Trace 新增 query ID、快照、各阶段耗时、融合前完整去重数、阶段排名、向量相似度、RRF 和 rerank 分数、查询 Embedding 状态和用量。关键词/向量并行耗时不直接相加作为总耗时。上游异常不回显原始错误文本。
- Run 详情保留公开事件时间、执行等待、首进展与首正式答案时延、检索、工具、最终引用和重试关系。工具前后来被丢弃的临时正文不算正式答案首 Token；直接回答仅在完成后确认。
- 汇总仅累计已知模型步骤用量，缓存/推理子项不重复加总；p50/p95 使用 nearest-rank，包含所展示终态 Run 的排队时间、失败与取消，并显示样本量。旧 Run 不用当前参数回填，也不把缺失用量当 0。
- 评测报告读取器支持固定 `evals/reports` 目录下的 `evaluation-report-v1` JSON，校验文件名、格式和 2 MB 上限，列表最多 50 个；支持版本与逐题查看。目前没有实际标准集或报告，界面如实展示未评测。固定命令、报告生成和基线比较仍属 D15。
