# 上传进度与视觉限额调整

## 本次调整

- 整体进度覆盖浏览器上传、文档解析、视觉识别、Embedding 和快照发布，不再在文件发送完成后直接显示 100%。
- 浏览器真实上传占 0%–10%；Workflow 按真实完成的文件与阶段推进 10%–99%；快照成功发布后写入 100%。
- 导入批次持久化 `progress_percent` 与 `progress_stage`，刷新页面后仍能从服务端读取当前进度。
- Embedding 每完成一批 Chunk 都会更新进度；解析和视觉识别在真实步骤完成后推进，不使用定时假进度。
- 批次轮询调整为每 2 秒一次、最长 30 分钟，避免较多视觉候选仍在运行时前端提前报超时。
- 单份文件视觉分析候选上限保持 20 张。
- 单批导入跨 PDF、Markdown、DOCX 和 XLSX 的视觉资产总上限由 70 张调整为 50 张。
- 单次导入的总文件数量上限保持 50 个，服务端继续同时校验直接上传和 ZIP 解压后的数量。

## 验证范围

- TypeScript 类型检查。
- 本次修改文件的 ESLint 检查。
- 数据库迁移生成及本地迁移执行。
- 上传组件的数据流检查：选择文件 → 上传区间 → 批次阶段轮询 → 快照发布 → 刷新知识库。
