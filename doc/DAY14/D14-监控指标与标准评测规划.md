# D14 监控指标与标准评测规划

状态：需求已确认，尚未实施。本次只更新计划，不表示页面、采集字段或评测集已经交付。范围以[整体计划第 10 节](../项目整体计划.md)为准。

## 用户目标

1. 集中看到所有可可靠采集或计算的相关指标，包括当前实际生效参数。
2. 按会话查看汇总，并深入每次 Run、每次检索、模型和工具调用。
3. 有一套固定、版本化的标准评测集，调整参数或提示词后重复运行，对比效果、耗时和费用。

## 页面结构

| 区域 | 展示内容 |
|---|---|
| 当前配置 | 实际模型、各阶段 Top K、融合/rerank、切块、超时、上下文、工具和费用限额、提示词版本；不展示密钥 |
| 指标总览 | 完整指标目录及来源/单位/口径，按类展开；状态、调用量、耗时分位数、用量/费用、队列及资源；缺失数据说明原因 |
| 会话详情 | Run 列表、重试关系、各状态数量、可用 Token/费用汇总、耗时及缺失覆盖率 |
| Run 详情 | 历史配置快照、模型/资料/提示词/代码版本；每次检索候选和排名、rerank 前后结果、已读与实际引用；逐调用用量/耗时/失败/重试 |
| 评测报告 | 数据集与评分版本、基线/候选配置差异、逐题结果、质量/费用/耗时差值、改善/回退、阻断项和报告导出 |

采用现有技术栈和组件，先做表格、筛选、详情及报告。实时推送、丰富趋势图、在线标注与在线参数编辑不在本次 P0 范围。

## 验收清单

- 当前配置来自真实生效值；修改参数后新 Run 使用新快照，历史 Run 保持旧值。
- 一个会话多个 Run、一个 Run 多次检索/模型调用均可追踪；事件重放/重试不重复统计费用与 Token。
- 运行上限、实测数量、质量评分分开；没有标注的普通会话不展示虚构 Recall 或正确率。
- 用量/费用缺失显示未采集或待对账，会话汇总标注覆盖率；模型 Token 子项不重复累加。
- 首个进展事件和首个正式答案 Token 延迟分开；p50/p95 有样本量、窗口及过滤口径。
- 每个评测样本包含固定资料/问题/多轮前置条件、预期或等价证据、评分规则和集合归属，不能只存一个问题列表。
- 同一命令可重复执行相同版本的数据，产生独立报告；报告可关联实际 Run/检索记录，不调用伪造结果的专用链路。
- 基线与候选报告展示配置/提示词差异、逐题改善及退化、聚合指标差值、失败与未评分；不同数据或评分版本明确提示不可直接比较。
- 检索指标区分阶段及文档/块粒度；@10 使用实际前 10 个候选，不能用最终 Top 6 冒充；标注分母与等价证据规则固定。
- 付费评测显式开启且有预算，评测 Run 与普通会话隔离标记；原始用户资料不自动加入长期样本集。
- 页面、详情、API 与报告导出均做 owner 权限检查；不暴露密钥、存储凭据或私密思维链。
