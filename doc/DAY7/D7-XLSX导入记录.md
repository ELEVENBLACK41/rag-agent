# DAY7：XLSX 导入、位置引用与内嵌图片

状态：已完成。基础实现、本地解析和本地真实导入链路均已验证；公开访客门禁仍待独立复验。

## 实现范围

- `.xlsx` 从附件职责调整为索引职责，并通过格式注册表分派给独立 `xlsx.ts` 解析器；Workflow 不包含 XLSX 条件分支。
- 使用锁定的 ExcelJS `4.4.0` 读取基础工作表和非空单元格；公式与文件保存的缓存值在同一文本块中明确区分，例如 `公式 = B2*C2；缓存值 = 36`。ExcelJS 不计算公式，未保存缓存值时显示“未提供”，不伪造计算结果。
- 文本 Chunk 使用 `工作表名称 + Excel 区域` 定位，如 `Overview · A1:D4`，不将工作表行误写为 Markdown 行号。
- XLSX 在交给 ExcelJS 解压前校验 ZIP 容器：拒绝加密和非 XLSX 容器，限制最多 1,000 个条目、总解压大小 50 MB；额外限制最多 50 张工作表、每张最多 10,000 个非空单元格。
- XLSX 内嵌 PNG/JPEG 使用 ExcelJS 公共图片 API 获取工作表和锚点单元格；复用跨格式视觉资产保存、模型版本、失败状态和检索 Chunk 事务。DOCX 与 XLSX 共同使用每文件 2 张、单图最小边长 16 像素、最大 2,000,000 像素、每批 5 张的图片预算边界，避免把供应商无法处理的极小图片送入模型。
- 视觉领域策略集中在 `visual/limits.ts`：PDF、DOCX 与 XLSX 共用批次总资产数、每文件候选数和图片像素边界；PDF 独有的渲染倍率和最长边也以 `PDF_` 前缀在同一文件维护。
- 新增视觉分析器注册表，以 MIME 分派 PDF/DOCX/XLSX。Workflow 只传递受校验的导入 ID 与 MIME 类型，不知道 Office 图片提取或模型调用细节。
- 引用标签和导入面板新增 XLSX 的“工作表 / 区域”及“工作表 / 锚点 / 内嵌图片”展示。

## 当前限制与待验收项

- 仅支持基础 XLSX 的工作表、非空单元格、公式及文件内缓存值、内嵌 PNG/JPEG；不承诺 XLSM 宏、图表语义、透视表、复杂公式重算、精确打印版式或 GIF。
- 公式缓存值由上传文件提供，ExcelJS 不充当公式引擎；缓存缺失时系统只保留公式，不将其计算成未经验证的值。
- 已验证本地环境中的真实 Gateway 视觉与 Embedding 调用、数据库导入批次、视觉资产持久化和快照发布；真实问答召回应随 DAY8 的聊天验收一并复验。
- 本次没有修改隔离、删除、存储或批次预算的既有门禁实现；D7 计划要求的访客隔离、删除和资源/预算门禁需与上述端到端导入一起复验，不能以本地解析通过替代。

## Fixture 兼容性说明

原有 XLSX fixture 无法被项目锁定的 ExcelJS `4.4.0` 读取。重建时曾验证当前 artifact 工具输出也触发相同 ExcelJS 兼容问题，因此最终固定样本由项目运行时使用的 ExcelJS 写出。这样 fixture 验证的是实际解析器能够消费的标准工作簿，而非仅验证另一个写入工具的输出。
